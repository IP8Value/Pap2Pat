## FIELD OF THE DISCLOSURE

The present disclosure relates to the field of computer science, specifically to the automated generation of formally verified parsers for programming languages and structured data formats. More precisely, the invention concerns a system and method for the mechanical derivation of parsing software that is guaranteed to terminate and produce semantically correct results with respect to a formally specified grammar, using a proof assistant to encode both the grammar and its associated semantic actions, and then extracting executable code from the verified formalization. The invention operates at the intersection of formal methods, programming language theory, and software verification, providing a novel approach to parser construction that eliminates the possibility of parsing errors arising from grammatical ambiguity, non-termination, or semantic misinterpretation. Unlike conventional parser generators that produce code from grammars without formal guarantees, this invention ensures that the resulting parser is correct by construction, meaning that its behavior is logically entailed by a machine-checked proof of its adherence to the semantics of parsing expression grammars augmented with semantic actions. The invention is particularly applicable to domains where correctness is paramount, including secure web infrastructure, compiler backends, protocol analyzers, configuration file interpreters, and safety-critical systems that process untrusted input. It further enables the integration of lexical and syntactic analysis into a single unified formalism, thereby eliminating the need for separate tokenization stages and reducing the risk of inconsistencies between lexical and syntactic layers. The system is designed to be used in environments where the cost of parsing failure is high, such as financial transaction systems, medical device software, aviation control systems, and cryptographic protocol implementations, where even minor parsing errors can lead to catastrophic security vulnerabilities or system crashes. The invention does not merely improve the efficiency or expressiveness of existing parser generators; it fundamentally redefines the relationship between grammar specification and parser implementation by embedding the entire parsing process within a formal logical framework, thereby enabling the generation of parsers that are not only correct but also provably so.

## BACKGROUND OF THE DISCLOSURE

Parsing has long been a foundational component of software systems, serving as the initial phase through which raw textual input is transformed into structured representations suitable for further processing. In the context of programming languages, parsing is the mechanism by which source code is converted into abstract syntax trees, enabling subsequent compilation, interpretation, or static analysis. Similarly, in data exchange protocols such as XML, JSON, and HTTP, parsing enables the translation of serialized formats into native data structures that applications can manipulate. Historically, parsing has been implemented using a variety of techniques, including recursive descent, LL and LR table-driven methods, and parser generators such as Yacc, Bison, ANTLR, and JavaCC. These tools typically accept a grammar expressed in a variant of Backus-Naur Form and generate code that attempts to recognize strings conforming to that grammar. However, despite their widespread use, these tools are not accompanied by formal guarantees regarding correctness, termination, or completeness. The generated parsers often contain hidden bugs, such as unintended left-recursion, ambiguous choices, or incorrect semantic actions, which may remain undetected until runtime. Even mature tools like Yacc, which have been in use for decades, are known to contain subtle implementation flaws that can lead to incorrect parsing behavior under certain input conditions. Furthermore, the separation between lexical analysis and syntactic analysis in traditional parser architectures introduces additional points of failure, as the tokenization phase must be carefully synchronized with the grammar rules, and mismatches between the two layers can result in silent parsing errors. The advent of parsing expression grammars offered a promising alternative to context-free grammars by introducing deterministic choice, greedy repetition, and syntactic predicates, which together eliminate ambiguity and allow for the seamless integration of lexical and syntactic rules. However, while PEGs are easier to implement and more expressive than traditional grammars, their implementation in practice still relies on manual coding or non-verified generator tools, leaving open the possibility of logical inconsistencies between the grammar specification and the actual parser behavior. Moreover, the issue of termination remains unresolved in many practical PEG implementations, as left-recursive grammars—common in real-world language definitions—can cause infinite loops during parsing. Although recent work has proposed solutions to handle left recursion through memoization or grammar transformation, these approaches are not formally verified and do not guarantee that the resulting parser will terminate on all inputs. The absence of formal verification in parsing systems has been a persistent gap in software reliability, particularly in contexts where security and correctness are non-negotiable. Formal verification of compilers, such as the CompCert project, has demonstrated the feasibility and value of mechanically proving the correctness of complex software systems, yet even these efforts begin their verification at the level of the abstract syntax tree, explicitly excluding the parser from the verified chain of trust. This leaves the parser as a critical, unverified component upon which the entire system depends. The invention disclosed herein addresses this fundamental limitation by providing a complete, end-to-end formal verification of the entire parsing pipeline, from grammar specification through semantic action integration to executable code generation, ensuring that every aspect of the parser’s behavior is logically entailed by a machine-checked proof. This represents a significant departure from prior art, which treats parsing as an engineering problem to be solved through heuristic optimization, rather than a mathematical problem to be solved through formal proof.

## SUMMARY

The invention provides a system and method for generating formally verified parsers from grammars expressed in extended parsing expression grammar form, using a proof assistant to encode the grammar, its semantic actions, and the semantics of parsing itself, and then extracting executable code from the verified formalization. The system ensures that the resulting parser is both correct and terminating on all possible inputs, thereby guaranteeing total correctness. The invention operates by first encoding a parsing expression grammar, including its non-terminals, terminals, and associated semantic actions, as a formal structure within the Coq proof assistant. Each production rule is represented as a dependent type, ensuring that the grammar is well-typed and free of undefined references. Semantic actions are embedded as Coq functions, whose termination is guaranteed by the totality of functions in Coq. The system then performs a formal analysis to determine whether the grammar is well-formed, meaning that it does not contain any form of left recursion—direct, indirect, or mutual—that could lead to non-termination. This analysis is performed via a fixed-point computation over the set of parsing expressions, using a set of inference rules that determine whether each expression can succeed without consuming input, can succeed after consuming input, or can fail. If the grammar is determined to be well-formed, the system constructs a formal interpreter for the grammar, implemented as a recursive function over parsing expressions and input strings, with a termination proof based on a well-founded measure derived from the semantics of parsing expression grammars. The interpreter is proven correct with respect to the formal semantics of extended parsing expression grammars, meaning that for any input string and any parsing expression, the output of the interpreter matches the result predicted by the formal semantics. The system then extracts the interpreter and its associated grammar into executable code in a target language such as OCaml, Haskell, or Scheme, discarding all proof obligations and logical artifacts, thereby producing a standalone parser that retains the correctness and termination guarantees of the formalization. The extracted parser is free of runtime errors arising from grammatical ambiguity, infinite recursion, or semantic misinterpretation, and is guaranteed to produce a parse tree or semantic value that is logically consistent with the original grammar. The invention further includes mechanisms for optimizing the extracted code, such as replacing inefficient list operations with linear-time alternatives, implementing native range operators to avoid combinatorial explosion, and redefining character representations to align with the target language’s native types. The system has been successfully applied to real-world grammars, including a complete grammar for the Java programming language and a grammar for XML, demonstrating that the resulting parsers achieve performance comparable to hand-optimized, non-verified parsers while providing formal guarantees of correctness. The invention enables the construction of parsers for safety-critical systems where the cost of parsing failure is unacceptable, and provides a foundation for future tools that may eliminate the need for users to interact with the proof assistant directly, thereby making formally verified parsing accessible to a broader audience of software developers.

## DETAILED DESCRIPTION OF ILLUSTRATIVE EMBODIMENTS

### 1. Generals Principles of An Embodiment of the Invention

The embodiment of the invention is grounded in the principle that parsing, as a computational process, can be entirely formalized within a proof assistant such as Coq, and that the resulting formalization can be mechanically transformed into executable code that retains the logical guarantees of its formal origin. This principle is realized through a deep embedding of parsing expression grammars and their associated semantic actions, where every component of the grammar—terminals, non-terminals, sequences, choices, repetitions, and semantic transformations—is represented as a data structure within the type theory of the proof assistant. Unlike shallow embeddings, which define parsers as higher-order functions over existing language constructs, this deep embedding treats the grammar as a first-class syntactic object, allowing for the application of formal analysis techniques such as termination checking and correctness proof. The grammar is encoded as a collection of mutually recursive definitions, each mapping a non-terminal symbol to a parsing expression, which itself is a recursively defined algebraic type representing the possible operations that can be performed during parsing. Each parsing expression is indexed by the type of semantic value it produces, ensuring that semantic actions are type-safe and that the output of parsing is always well-typed. The semantics of parsing is then formally defined as a relation between a parsing expression, an input string, and a result, where the result is either a failure or a success containing a remaining input string and a computed semantic value. This semantic relation is proven to be deterministic, meaning that for any given input and expression, there is at most one possible outcome, thereby ensuring that the grammar is unambiguous. The key innovation lies in the formal proof that this semantic relation is total for well-formed grammars, meaning that every possible input string will lead to either a successful parse or a definitive failure, with no possibility of non-termination. To achieve this, the invention implements a syntactic analysis procedure that examines the structure of the grammar to determine whether any non-terminal can lead to an infinite loop through left recursion. This analysis is performed by iteratively computing the set of parsing expressions that can succeed without consuming input, those that can succeed only after consuming input, and those that can fail. The union of these sets is then used to determine whether every expression in the grammar is well-formed, meaning that it cannot lead to a non-terminating parse. If the grammar passes this analysis, the system constructs a recursive interpreter that mirrors the formal semantics, with each case of the interpreter corresponding to a clause in the semantic definition. The termination of this interpreter is established by defining a well-founded measure based on the number of parsing steps and the length of the remaining input, ensuring that each recursive call reduces this measure in a way that guarantees eventual termination. The interpreter is then proven correct by induction over the structure of the parsing expression and the input string, demonstrating that its output matches the result predicted by the formal semantics. Once the correctness and termination of the interpreter have been formally established, the system uses the extraction mechanism of the proof assistant to generate executable code in a conventional programming language. During extraction, all proof terms, logical assertions, and type-level annotations are discarded, leaving only the computational content of the interpreter and the grammar. The resulting code is a standalone parser that can be integrated into any software system without requiring the presence of the proof assistant or any knowledge of formal methods. The parser is guaranteed to terminate on all inputs and to produce outputs that are logically consistent with the original grammar, thereby providing total correctness without sacrificing practicality. This embodiment fundamentally transforms the role of the parser from a fragile, error-prone component into a mathematically certified module, enabling the construction of software systems whose correctness can be traced back to a formal proof rather than empirical testing.

### Example 1

An illustrative embodiment of the invention is demonstrated through the formal specification and extraction of a parser for simple arithmetic expressions, a canonical example in parsing literature. The grammar for this example consists of five non-terminals: ws, number, term, factor, and expr, each corresponding to a syntactic category in the language of arithmetic expressions. The ws non-terminal is defined to consume zero or more whitespace characters, ensuring that spaces between tokens do not interfere with parsing. The number non-terminal matches a sequence of one or more decimal digits and converts them into their numeric value using a semantic action that transforms the list of characters into a natural number. The factor non-terminal matches either a parenthesized expression or a number, while the term non-terminal matches a sequence of factors separated by multiplication operators, and the expr non-terminal matches a sequence of terms separated by addition operators. Each of these productions is augmented with semantic actions that compute the value of the expression as it is parsed, using projections to extract the values of sub-expressions and applying arithmetic operations to combine them. This grammar is encoded in Coq as a set of mutually recursive definitions, each expressed as a value of the PExp type, indexed by the appropriate semantic type. The semantic type for expr is defined as a natural number, reflecting the fact that the parser evaluates expressions to their numeric result. The grammar is then subjected to the well-formedness analysis, which verifies that no non-terminal can lead to left recursion. In this case, the analysis confirms that the grammar is well-formed because the recursive calls in expr and term are right-recursive, meaning that each recursive invocation consumes at least one token before recursing, thereby ensuring termination. The interpreter is then constructed as a recursive function that pattern-matches on the structure of the parsing expression and applies the corresponding semantic rule. For example, when encountering a sequence expression such as expr ; term, the interpreter first parses the expr component, and if successful, uses the remaining input to parse the term component, combining the results via a semantic action that performs addition. The correctness of this interpreter is proven by induction over the structure of the parsing expression and the input string, demonstrating that for every possible input, the output of the interpreter matches the result predicted by the formal semantics. Once the proof is complete, the system extracts the interpreter and its associated grammar into OCaml code, producing a standalone function that takes a string as input and returns either a failure or a natural number representing the evaluated expression. This extracted parser is then tested against a variety of inputs, including "(1+2)*3", "10+20*5", and "((1))", and consistently produces the correct result. The performance of the extracted parser is measured and found to be competitive with hand-written parsers, despite the absence of manual optimization. The parser is also tested against malformed inputs such as "1++2" and "(1", and correctly reports failure in each case, demonstrating that it does not produce false positives. This example illustrates the core principle of the invention: that a grammar, when formally specified and verified, can be transformed into a parser that is not only correct but also reliable, efficient, and deployable in production environments without the need for additional testing or validation.

### 2. Description of Some Embodiments

The invention encompasses several distinct but interrelated embodiments, each addressing a different aspect of the overall system for generating formally verified parsers. One embodiment concerns the encoding of parsing expression grammars within the Coq proof assistant, where each production rule is represented as a dependent type indexed by the semantic value it produces. This encoding ensures that the grammar is type-safe and that semantic actions are applied only to compatible types, preventing runtime type errors. Another embodiment involves the formal definition of the semantics of extended parsing expression grammars, which is expressed as a relation between a parsing expression, an input string, and a result, where the result is either a failure or a success containing a remaining string and a semantic value. This semantics is proven to be deterministic, meaning that for any given input and expression, there is at most one possible outcome, thereby ensuring that the grammar is unambiguous. A third embodiment is the well-formedness analysis, which systematically examines the grammar to detect any form of left recursion that could lead to non-termination. This analysis is implemented as a fixed-point computation over the set of parsing expressions, using a set of inference rules that determine whether each expression can succeed without consuming input, can succeed after consuming input, or can fail. The analysis is proven to be sound, meaning that if a grammar is determined to be well-formed, then it is guaranteed to terminate on all inputs. A fourth embodiment is the construction of the formal interpreter, which is implemented as a recursive function that mirrors the formal semantics of the grammar. The interpreter is proven correct by induction over the structure of the parsing expression and the input string, demonstrating that its output matches the result predicted by the formal semantics. A fifth embodiment concerns the extraction of the interpreter and its associated grammar into executable code in a target language such as OCaml, Haskell, or Scheme. During extraction, all proof terms and logical artifacts are discarded, leaving only the computational content of the interpreter, thereby producing a standalone parser that retains the correctness and termination guarantees of the formalization. A sixth embodiment involves the optimization of the extracted code, including the replacement of inefficient list operations with linear-time alternatives, the implementation of native range operators to avoid combinatorial explosion, and the redefinition of character representations to align with the target language’s native types. A seventh embodiment is the application of the system to real-world grammars, such as the complete grammar for the Java programming language and a grammar for XML, demonstrating that the resulting parsers achieve performance comparable to hand-optimized, non-verified parsers while providing formal guarantees of correctness. An eighth embodiment concerns the integration of the system into a larger software platform, such as the One Pot Application web development framework, where the verified parser serves as a critical component in the processing of user input, configuration files, and protocol messages. A ninth embodiment involves the development of a bootstrapping mechanism that allows users to specify grammars in a simple textual format, which is then parsed by a preliminary version of the system to generate a Coq-encoded grammar, thereby eliminating the need for users to interact directly with the proof assistant. A tenth embodiment is the extension of the system to support error reporting, where the interpreter is modified to track the position of the input string during parsing and to generate informative error messages when parsing fails, thereby improving usability without compromising correctness. Each of these embodiments contributes to the overall functionality of the invention, and together they form a comprehensive system for the generation of formally verified parsers that are correct, terminating, and practical.

### 3. Summary of Three Embodiments of the Invention

The first embodiment of the invention is a formal encoding of extended parsing expression grammars within the Coq proof assistant, where each grammar is represented as a collection of dependent types that encode both the syntactic structure of the grammar and the semantic actions associated with each production. This encoding ensures that the grammar is well-typed, free of undefined references, and logically consistent, and that semantic actions are applied only to compatible types. The second embodiment is a formal analysis procedure that determines whether a given grammar is well-formed, meaning that it does not contain any form of left recursion—direct, indirect, or mutual—that could lead to non-termination. This analysis is performed by iteratively computing the set of parsing expressions that can succeed without consuming input, those that can succeed only after consuming input, and those that can fail, and then verifying that every expression in the grammar belongs to one of these sets. The third embodiment is a formally verified interpreter for extended parsing expression grammars, implemented as a recursive function that mirrors the formal semantics of the grammar and is proven correct and terminating for all well-formed grammars. This interpreter is then extracted into executable code in a target language such as OCaml, producing a standalone parser that retains the correctness and termination guarantees of the formalization. These three embodiments work in concert to provide a complete system for generating formally verified parsers: the first ensures that the grammar is logically sound, the second ensures that the parser will terminate, and the third ensures that the parser behaves correctly. Together, they enable the construction of parsers that are not only correct by construction but also practical for deployment in real-world applications, thereby bridging the gap between formal verification and software engineering.
