# DESCRIPTION

## TECHNICAL FIELD

The present invention relates to cryptographic systems and methods for secure multi-party computation, specifically to protocols for performing secure integer comparison between two parties without revealing any information beyond the outcome of the comparison. The invention is particularly suited for applications in privacy-preserving machine learning, secure benchmarking, private auctions, biometric authentication, and other domains where sensitive numerical data must be compared under strict confidentiality constraints. The invention leverages homomorphic encryption schemes—both additively homomorphic and fully homomorphic—to enable a server to evaluate a binary tree structure representing one party’s private input while processing an encrypted version of the other party’s input, thereby computing a comparison result that is only decryptable by the client. The protocol operates in a single communication round, minimizes computational overhead through optimized data structures and precomputed dependency graphs, and supports both constant-input and encrypted-input variants with provable security under standard cryptographic assumptions. This invention improves upon prior art by reducing computational complexity, eliminating the need for multiple rounds of interaction, and enabling efficient deployment on resource-constrained environments such as mobile devices or embedded systems without sacrificing security or correctness.

## RELATED ART

Secure integer comparison has long been recognized as a foundational primitive in secure multi-party computation, with applications spanning privacy-preserving classification in machine learning, fair auction mechanisms, confidential financial benchmarking, and biometric matching systems. Early work by Yao introduced the seminal “Millionaires’ Problem,” wherein two parties seek to determine which holds a greater value without disclosing their actual wealth. Subsequent efforts have sought to realize this functionality efficiently under various cryptographic models. One prominent approach employs garbled circuits, as proposed by Kolesnikov et al., which provide general-purpose secure computation but suffer from high communication and computational costs due to the need to encrypt and evaluate entire Boolean circuits. Another widely adopted technique is based on additively homomorphic encryption (AHE), exemplified by the DGK protocol, which decomposes integers into their binary representations and performs bitwise comparisons using homomorphic operations. This method requires the server to evaluate a sequence of homomorphic comparisons between corresponding bits of the inputs, followed by aggregation of results through modular arithmetic. Subsequent optimizations by Veugen reduced the number of homomorphic additions required, while Joye and Salehi further improved efficiency by halving the number of transmitted ciphertexts through clever masking techniques. However, these protocols remain limited in that they require multiple rounds of interaction, especially when both inputs are encrypted, and rely on specific AHE schemes such as Paillier, which are incompatible with elliptic curve-based implementations due to the need for large modulus arithmetic and discrete logarithm computations.

More recent approaches have explored the use of fully homomorphic encryption (FHE) to perform comparisons directly on encrypted data without requiring bit decomposition. Cheon et al. proposed a protocol based on evaluating a product of differences between corresponding bits, achieving logarithmic multiplicative depth through recursive binary tree constructions of intermediate products. While this method reduces the number of homomorphic operations compared to DGK-style protocols, it requires the server to dynamically construct and evaluate a complex binary tree of products during each execution, necessitating substantial memory allocation and real-time computation of prefix products. Furthermore, the absence of precomputation means that each execution must independently perform the same intricate tree-building and traversal logic, leading to significant latency in repeated comparisons. Other protocols have attempted to leverage arithmetic black-box models or secret sharing schemes, which offer unconditional security and low local computation costs but require an offline preprocessing phase to generate Beaver triples, secure communication channels to prevent share reconstruction, and multiple rounds of interaction among parties. These requirements render them unsuitable for scenarios involving two-party interactions with asymmetric roles, such as client-server architectures common in cloud-based privacy-preserving analytics. Moreover, many existing protocols lack support for shared output bits, encrypted inputs, or less-than comparisons without introducing additional rounds or complex modifications. None of the prior art provides a unified, single-round protocol that simultaneously supports both AHE and FHE instantiations, enables encrypted inputs without additional rounds, incorporates precomputed dependency structures to minimize multiplicative depth, and achieves superior performance across all bit-lengths without relying on specialized encryption schemes or assumptions beyond IND-CPA security. The present invention overcomes these limitations by introducing a novel binary tree-based comparison framework that decouples the tree structure from the input values, enables efficient evaluation through precomputed multiplication paths, and unifies the handling of encrypted and plaintext inputs under a single protocol architecture.

## SUMMARY

The invention discloses a novel protocol for secure integer comparison between two parties, wherein one party, referred to as the server, holds a private integer input and the other party, referred to as the client, holds a second private integer input. The protocol enables the server to compute a comparison result indicating whether the client’s input is greater than or equal to the server’s input, without learning any information about the client’s input beyond what is implied by the result, and without the client learning anything about the server’s input beyond the final comparison bit. The protocol operates in a single communication round and is instantiated using either additively homomorphic encryption (AHE) or fully homomorphic encryption (FHE), with distinct but structurally consistent algorithms for each variant. The core innovation lies in the construction of a binary tree, referred to as a comparison tree, that encodes the server’s input in a manner that allows the server to evaluate all possible paths of the client’s encrypted input simultaneously, aggregating results in a way that isolates the comparison outcome to a single, decryptable value. For the AHE instantiation, the server constructs a tree where only paths corresponding to inputs greater than or equal to its own are retained, and the client’s encrypted bits are compared against edge labels using homomorphic subtraction, with path weights adjusted by powers of two to prevent cancellation of non-zero results. For the FHE instantiation, the server constructs a tree where edge labels are compared using homomorphic equality tests, and path results are aggregated via multiplication, yielding a single encrypted bit indicating the comparison outcome. In both cases, the tree structure is optimized to minimize the number of homomorphic operations and, in the FHE case, to reduce multiplicative depth to logarithmic order through precomputed dependency lists that define the order of multiplications along each path. The server does not need to know the client’s input in plaintext, and in an extended variant, both inputs may be encrypted, with the client assisting in the evaluation through homomorphic operations that preserve privacy. The protocol further supports shared output bits, allowing the comparison result to be split between the two parties as additive shares, and supports less-than comparisons through a symmetric inversion of the tree structure. The invention eliminates the need for multiple communication rounds, avoids reliance on specific encryption schemes beyond standard IND-CPA security, and achieves superior computational efficiency over prior art by leveraging precomputed, input-independent tree structures and optimized aggregation techniques. The protocol is secure in the semi-honest model, as demonstrated by the existence of efficient simulators that can reproduce the view of either party using only their input and output, without access to intermediate messages. The invention is particularly advantageous in applications requiring repeated comparisons, such as decision tree evaluation in private machine learning, where the same tree structure can be precomputed once and reused across thousands of queries, yielding substantial performance gains.

## DETAILED DESCRIPTION

The present invention provides a comprehensive protocol for secure integer comparison between two parties, wherein one party, designated as the server, possesses a private integer input, and the other party, designated as the client, possesses a second private integer input. The goal of the protocol is to determine whether the client’s input is greater than or equal to the server’s input, such that the server learns nothing about the client’s input beyond the final comparison result, and the client learns nothing about the server’s input beyond the same result. The protocol is designed to operate in a single communication round, ensuring minimal latency and suitability for real-time applications. It is instantiated under two distinct cryptographic frameworks: additively homomorphic encryption (AHE) and fully homomorphic encryption (FHE), each requiring a tailored algorithmic approach while preserving the underlying structural principles. The core innovation of the invention resides in the construction of a binary tree representation of the server’s input, known as a comparison tree, which encodes all possible outcomes of the comparison in a manner that permits the server to evaluate the client’s encrypted input across all possible paths simultaneously, without revealing any intermediate values or structural details of the server’s input. The tree is constructed such that exactly one path leads to a distinguishable result—either a single encrypted bit equal to one in the FHE case or a single encrypted zero in the AHE case—while all other paths yield indistinguishable or non-zero results, thereby enabling the client to decode the outcome upon decryption without exposing any auxiliary information.

In the initialization phase, the client generates a key pair for a homomorphic encryption scheme, comprising a public key, a private key, and, in the case of FHE, an evaluation key. The public key and evaluation key are transmitted to the server, while the private key remains securely held by the client. This setup ensures that all subsequent communication is encrypted under the client’s public key, guaranteeing that only the client can decrypt the final result. The server, upon receiving the public key, constructs a binary tree whose structure is determined solely by the bit-length of the inputs, which is assumed to be publicly known. The tree is not constructed from the server’s input in plaintext but rather from a canonical representation that encodes the relative ordering of the server’s input within the space of all possible bitstrings of the given length. This representation ensures that the tree’s topology remains invariant under re-encryption of the server’s input, making it suitable for scenarios where both inputs are encrypted. For each bit of the server’s input, the tree branches in a manner that reflects the binary representation of the input, with left edges labeled as zero and right edges labeled as one, and terminal nodes assigned labels that indicate whether a path corresponds to an input greater than or equal to the server’s value. The tree is pruned to eliminate redundant subtrees, resulting in a half-pruned structure that contains exactly 𝜇 inner nodes and 𝜇 + 1 leaf nodes for an input of bit-length 𝜇, thereby minimizing the number of operations required during evaluation.

In the FHE instantiation, the server evaluates the client’s encrypted input by traversing the tree and computing, at each edge, a homomorphic equality test between the bit of the client’s input and the label of the edge. This equality test is implemented using a homomorphic XNOR operation, which returns a ciphertext encrypting one if the bits match and zero otherwise. The results along each path from the root to a leaf are aggregated via homomorphic multiplication, yielding a ciphertext at each leaf that encrypts one if the client’s input matches the path exactly and zero otherwise. The leaf nodes are then labeled according to whether they correspond to inputs greater than or equal to the server’s input, with those nodes assigned a label of one and others assigned a label of zero. The server computes the product of each leaf’s path result and its label, then sums all such products using homomorphic addition, resulting in a single ciphertext that encrypts one if the client’s input is greater than or equal to the server’s input and zero otherwise. This final ciphertext is transmitted to the client, who decrypts it using their private key to obtain the comparison result. To reduce the multiplicative depth of the protocol, which is critical for leveled FHE schemes with fixed computational capacity, a precomputed dependency list is generated offline. This list defines the optimal order of multiplications along each path, ensuring that the depth of the circuit remains logarithmic in the bit-length rather than linear. The dependency list is computed once for a given bit-length and can be reused across all subsequent comparisons, enabling efficient deployment in environments where thousands of comparisons are performed using the same tree structure.

In the AHE instantiation, the server constructs a similar tree, but the evaluation mechanism differs significantly due to the limitations of additive homomorphism. Instead of equality testing, the server computes a homomorphic inequality test between the client’s encrypted bits and the edge labels, using homomorphic subtraction to determine whether the bits differ. This yields a value of zero if the bits match and a non-zero value otherwise. However, because subtraction in AHE can produce negative results, such as zero minus one yielding negative one, the aggregation of path results could lead to cancellation effects where multiple non-zero values sum to zero, falsely indicating a match. To prevent this, the server applies a weighting scheme to each bit position, multiplying the result of the comparison at level 𝑖 by 2^𝑖 before aggregating the path. This ensures that even if a path contains both positive and negative values, the weighted sum cannot be zero unless all individual comparisons yield zero, which occurs only when the client’s input exactly matches the path. The server then aggregates the weighted results along each path using homomorphic addition, resulting in a set of ciphertexts, one per leaf, where at most one encrypts zero and all others encrypt non-zero random values. To prevent the server from learning which leaf corresponds to the zero result, the server randomizes the order of the ciphertexts by permuting them and appending additional random ciphertexts that encrypt non-zero values, ensuring that the client receives a list of exactly 𝜇 ciphertexts, among which at most one encrypts zero. The client decrypts each ciphertext and determines the comparison result by checking whether any of the decrypted values equals zero. If so, the result is one; otherwise, it is zero. This approach ensures that the server learns nothing about the client’s input, as the permutation and randomization make it computationally infeasible to infer which path was matched, and the client learns nothing about the server’s input beyond the final bit.

The protocol further supports an extended variant in which both the client’s and server’s inputs are encrypted. In this scenario, the server does not possess the server’s input in plaintext but instead receives an encrypted version of it from a third party or from the client itself. The server then constructs the comparison tree using homomorphic operations to compute the necessary edge labels and leaf labels without ever decrypting the server’s input. For FHE, this is straightforward, as the server can perform homomorphic comparisons and label assignments directly on the encrypted bits. For AHE, the server must simulate the necessary operations using homomorphic addition and multiplication, including the computation of the inverse bit and the XOR operation, which is implemented as a subtraction. The same weighting scheme is applied to prevent cancellation, and the resulting ciphertexts are permuted and transmitted to the client for decryption. The protocol also supports the generation of shared output bits, wherein the comparison result is split between the two parties as additive shares. The server randomly selects a bit and computes the comparison under either a greater-than-or-equal or less-than functionality, ensuring that the tree structure remains identical regardless of the operation performed. The server then transmits the encrypted result to the client, who decrypts it to obtain their share, and the two parties can reconstruct the full comparison result by combining their shares through a homomorphic XOR operation. This feature is particularly valuable in multi-step protocols where the comparison result must be used as input to subsequent computations without revealing it to either party in full.

The invention further includes an optimized implementation that replaces the explicit binary tree structure with a two-dimensional array, thereby reducing memory overhead and simplifying the evaluation process. The array consists of 𝜇 + 1 rows and three columns, where the first column stores the bits of the server’s input along the leftmost path, the second column stores the negation of those bits, and the third column stores the leaf labels. The evaluation proceeds row by row, with homomorphic operations applied between adjacent cells to propagate path results, and the dependency list is applied to the array to define the multiplication order in the FHE case. This representation enables the protocol to be implemented with minimal computational overhead and is particularly suited for hardware acceleration or embedded deployment. The dependency list, which is precomputed offline and independent of the actual inputs, is stored as a static parameter and can be distributed publicly, allowing any party to implement the protocol without needing to compute the dependency structure themselves. This decoupling of structure from input data enables the protocol to be deployed in scalable environments where the same tree structure is reused across multiple comparisons, such as in private decision tree classifiers or secure benchmarking systems.

The security of the protocol is formally established under the semi-honest model, wherein both parties are assumed to follow the protocol correctly but may attempt to infer additional information from the messages they receive. For both the FHE and AHE instantiations, simulators are constructed that, given only the input and output of each party, can generate a view indistinguishable from the actual protocol execution. In the FHE case, the server’s view consists of encrypted client bits and intermediate ciphertexts, all of which can be simulated by generating random ciphertexts under the public key, as the encryption scheme is IND-CPA secure. The client’s view consists of a single encrypted bit, which can be simulated by generating a random bit and encrypting it. In the AHE case, the server’s view consists of encrypted client bits and a permuted list of ciphertexts, all of which can be simulated by generating random non-zero ciphertexts and a single random zero ciphertext at a random position. The client’s view consists of a list of 𝜇 ciphertexts, which can be simulated by generating 𝜇 random ciphertexts, one of which is chosen uniformly at random to be a zero encryption. The existence of these simulators demonstrates that the protocol reveals no information beyond the final comparison bit, satisfying the formal definition of secure computation. The protocol is furthermore correct, as the mathematical structure of the comparison tree guarantees that the only path that yields a distinguishable result is the one corresponding to the true comparison outcome, and all other paths yield results that are either zero in the FHE case or non-zero in the AHE case, ensuring that the client always decrypts the correct bit.

The efficiency of the protocol is analyzed in terms of the number of homomorphic operations required for node evaluation, path aggregation, and leaf combination. For FHE with binary encoding, the protocol requires 2𝜇 homomorphic additions and 𝜇 - 1 multiplications in the basic variant, and 3𝜇 additions and 4𝜇 - 2 multiplications in the encrypted-input variant, with multiplicative depth reduced to log 𝜇 through the use of precomputed dependency lists. For AHE, the basic variant requires 3𝜇 - 2 homomorphic additions, while the encrypted-input variant requires 3𝜇 - 1 additions plus 2𝜇 constant multiplications by powers of two, which are implemented using repeated homomorphic additions. These figures represent a significant improvement over prior art, as the DGK protocol requires 7𝜇 additions and additional modular inverses, while Veugen’s optimization requires 4𝜇 additions and still relies on Paillier encryption for encrypted inputs, which introduces additional computational overhead. The elimination of multiple rounds, the avoidance of specialized encryption schemes, and the use of precomputed dependency structures collectively enable the protocol to outperform existing methods across all bit-lengths, as demonstrated by experimental evaluations on both laptop and server-grade hardware. The protocol is implemented using elliptic curve ElGamal for AHE and the BGV scheme for FHE, with performance benchmarks showing a 45% reduction in running time compared to DGK and a 63% reduction in the encrypted-input variant. The invention thus provides a unified, efficient, and secure foundation for secure integer comparison that is suitable for deployment in a wide range of privacy-preserving applications.
