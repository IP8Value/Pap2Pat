# DESCRIPTION

## TECHNICAL FIELD

The present invention relates generally to the field of secure multi-party computation and, more specifically, to systems and methods for performing secure integer comparison between two parties using homomorphic encryption. The invention provides a novel protocol that enables a client and a server to determine whether the client's private integer input is greater than or equal to the server's private integer input without revealing any additional information about either party's input beyond the comparison result itself. This technical solution operates within the domain of cryptographic protocols designed to preserve data privacy during collaborative computations, particularly in scenarios where sensitive numerical data must be compared without disclosure of the actual values. The invention leverages both fully homomorphic encryption (FHE) and additively homomorphic encryption (AHE) schemes to implement efficient, non-interactive comparison protocols that significantly reduce computational overhead compared to existing approaches. The technical field encompasses applications in privacy-preserving machine learning, secure benchmarking, electronic auctions, biometric authentication systems, and other domains where confidential numerical comparisons are required while maintaining strict data confidentiality requirements.

## RELATED ART

Secure integer comparison has been a fundamental problem in cryptography since Yao introduced the Millionaire's Problem in his seminal 1982 paper, which posed the challenge of determining which of two millionaires is wealthier without revealing their actual wealth amounts. This foundational work established the theoretical basis for secure multi-party computation (MPC) protocols that enable parties to compute functions on their private inputs while preserving input privacy. Over the decades, numerous approaches have been developed to address secure integer comparison, each with varying trade-offs in terms of computational complexity, communication overhead, security assumptions, and practical efficiency.

One prominent line of research employs garbled circuits, as demonstrated by Kolesnikov et al., who proposed schemes utilizing this technique for secure comparison operations. Another significant approach is the DGK protocol introduced by Damgård, Geisler, and Krøigaard, which relies on additively homomorphic encryption (AHE) and requires parties to evaluate encrypted input bits through a series of homomorphic operations. The DGK protocol has been subject to several optimizations, including improvements by Veugen and Joye and Salehi, which sought to reduce computational overhead and enhance security properties. Additional AHE-based protocols have been proposed by Lin and Tzeng, Fischlin, Blake and Kolesnikov, and Garay et al., each contributing variations on the fundamental approach of leveraging homomorphic properties for secure comparison.

Alternative methodologies have emerged based on the arithmetic black-box (ABB) model, which serves as a powerful abstraction commonly employed in MPC frameworks such as MP-SPDZ and SCALE-MAMBA. These ABB-based protocols typically decompose integers into their bit representations and perform equality comparisons on individual bits before aggregating results to determine the overall comparison outcome. Recent advancements in this domain include work by Cheon et al., who proposed schemes evaluating specific circuits using somewhat homomorphic encryption (SHE) or fully homomorphic encryption (FHE), and more contemporary research by Bourse et al. and Iliashenko and Zucca, who explored alternative representations using bases greater than binary to reduce comparison complexity.

Despite these advances, existing solutions face several limitations that the present invention addresses. Many protocols require multiple rounds of communication between parties, increasing latency and network overhead. Some approaches are restricted to specific encryption schemes or cannot handle scenarios where both inputs are encrypted simultaneously. Others suffer from high computational complexity due to linear multiplicative depth requirements in FHE implementations or inefficient path evaluation strategies in tree-based approaches. Additionally, certain protocols cannot support shared output bits or lack flexibility in handling different comparison operations such as less-than versus greater-than-or-equal-to comparisons. The present invention overcomes these limitations by introducing a novel binary tree-based protocol that achieves significant performance improvements while maintaining strong security guarantees and supporting multiple operational variants.

## SUMMARY

The present invention provides a novel system and method for secure integer comparison between two parties using homomorphic encryption, specifically designed to overcome limitations in existing protocols while achieving substantial performance improvements. The core innovation lies in representing the comparison problem as a classification task using a decision tree structure, where the server constructs a binary tree based on its private input and the client's encrypted input is evaluated against this tree structure without revealing either party's actual values.

In accordance with the invention, a server holding a private integer input y and a client holding a private integer input x can securely determine whether x ≥ y without disclosing their respective inputs beyond the comparison result. The protocol operates by having the server construct a specialized binary tree representation of its input y, where leaf nodes are appropriately labeled to reflect the comparison semantics. The client encrypts its input x using either a fully homomorphic encryption (FHE) scheme or an additively homomorphic encryption (AHE) scheme and transmits the encrypted input to the server. The server then evaluates the encrypted input against the constructed tree structure through a series of homomorphic operations, ultimately producing an encrypted result that the client can decrypt to obtain the comparison outcome.

The invention provides two primary variants of the protocol: a basic variant where only the client's input is encrypted while the server's input remains in plaintext, and an extended variant where both inputs are encrypted. In the basic variant, the server can optimize computation by considering only paths that could potentially evaluate to the positive comparison result, significantly reducing the number of required homomorphic operations. In the encrypted inputs variant, the protocol employs a normalized tree structure that maintains consistent topology regardless of the actual input values, thereby preventing information leakage about the server's input through tree structure analysis.

A key technical advancement of the invention is the introduction of optimized data structures and evaluation procedures that dramatically reduce computational complexity. Rather than implementing the protocol using traditional binary tree representations, the invention utilizes a two-dimensional array structure that simplifies implementation while maintaining equivalent functionality. Furthermore, for FHE implementations, the invention incorporates pre-computed dependency lists that enable logarithmic multiplicative depth rather than linear depth, substantially improving performance in leveled FHE schemes that have fixed circuit depth limitations.

The protocol supports multiple extensions and operational modes, including shared output bits where the comparison result is secret-shared between both parties, less-than comparison operations through inverse tree structures, and specialized handling for edge cases such as comparison with zero in AHE implementations. Security analysis demonstrates that the protocol maintains semi-honest security under standard IND-CPA assumptions for the underlying homomorphic encryption schemes, ensuring that neither party learns anything beyond their permitted outputs.

Experimental evaluation demonstrates significant performance improvements over existing state-of-the-art protocols. In the basic variant with only the client's input encrypted, the invention achieves a 45% reduction in running time compared to the original DGK protocol and approximately 10% improvement over Veugen's optimized DGK implementation. For the encrypted inputs variant where both parties' inputs are encrypted, the invention achieves more than 63% reduction in running time compared to existing approaches. These performance gains translate directly to practical applications in privacy-preserving machine learning, secure benchmarking, electronic auctions, and biometric authentication systems, where secure integer comparison serves as a fundamental building block.

## DETAILED DESCRIPTION

The present invention provides a comprehensive system and method for secure integer comparison between two parties using homomorphic encryption, addressing critical limitations in existing protocols while achieving substantial performance improvements. The detailed description begins with the fundamental architecture and operational principles, followed by specific implementations for different homomorphic encryption schemes, extensions for various operational requirements, security considerations, and practical implementation details.

The core architecture involves two parties: a client holding a private μ-bit integer input x and a server holding a private μ-bit integer input y, where μ represents the publicly known bit-length of the inputs. The objective is to securely compute the comparison function b = [x ≥ y], where b equals 1 if x is greater than or equal to y, and 0 otherwise, while ensuring that neither party learns anything beyond their permitted outputs. The protocol operates in a single round: the client generates appropriate cryptographic keys, encrypts its input, transmits the encrypted input to the server, the server performs homomorphic computations on the encrypted data using its private input, and returns an encrypted result to the client, which then decrypts to obtain the final comparison outcome.

The fundamental insight driving the invention is the recognition that the integer comparison problem can be effectively modeled as a classification problem using a decision tree structure. Specifically, given the server's input y, any client input x can be classified as either satisfying x ≥ y (resulting in classification label 1) or not satisfying this condition (resulting in classification label 0). The server constructs a specialized binary tree representation of its input y, where the tree structure encodes the comparison semantics such that evaluating any input x against this tree yields the correct comparison result.

The tree construction process varies depending on whether the server's input y is available in plaintext or encrypted form. When y is available in plaintext (basic variant), the server constructs what is termed a "half-pruned comparison tree" through an efficient traversal process. Starting from the root node, the server processes each bit of y from most significant to least significant. For each bit position i where y[i] = 1, the server inserts a leaf node on the left branch labeled with 0 (indicating values less than y at this position) and continues traversal down the right branch. Conversely, when y[i] = 0, the server inserts a leaf node on the right branch labeled with 1 (indicating values greater than or equal to y at this position) and continues traversal down the left branch. This construction ensures that the resulting tree contains exactly μ + 1 leaf nodes and μ inner nodes, with the tree structure optimized to minimize unnecessary computations.

When both inputs are encrypted (extended variant), the server cannot directly access the plaintext bits of y to construct the tree. Instead, the invention introduces a "normal comparison tree" structure that maintains consistent topology regardless of the actual input values. This normalized structure features a leftmost path of length μ labeled with the bits of y, with each inner node on this path having a right child leaf node. The edge labels and leaf labels are determined through homomorphic computations on the encrypted bits of y, ensuring that the tree structure itself does not reveal information about y's value. Specifically, for each encrypted bit b of y, the server homomorphically computes the encrypted inverse bit (1 - b) and uses these values to properly label the tree edges and leaves according to predefined rules that maintain the comparison semantics.

The evaluation process differs between FHE and AHE implementations due to their distinct homomorphic properties. In FHE implementations, the server performs bit equality tests between the client's encrypted input bits and the tree edge labels. For each path from root to leaf, the server homomorphically multiplies the equality test results along the path, yielding a value of 1 for the unique path corresponding to the correct classification and 0 for all other paths. The final result is obtained by homomorphically multiplying each path result with its corresponding leaf label and summing all products, producing a single encrypted bit representing the comparison outcome.

In AHE implementations, the evaluation process employs bit inequality tests rather than equality tests. For each path, the server homomorphically adds the inequality test results along the path, yielding a sum of 0 for the unique path corresponding to the correct classification (where all bits match) and a non-zero sum for all other paths (where at least one bit differs). The server then randomizes the encrypted path sums, permutes their order, and adds additional random ciphertexts to prevent information leakage about the tree structure. The client decrypts the received ciphertexts and determines the comparison result based on whether any ciphertext decrypts to zero.

A critical optimization in the invention involves the replacement of traditional binary tree data structures with a two-dimensional array representation. This array has dimensions (μ + 1) × 3, where the first column stores the labels along the leftmost path, the second column stores intermediate computation results, and the third column stores leaf labels. This representation simplifies implementation while maintaining equivalent functionality and enables more efficient memory usage and computation patterns.

For FHE implementations, particularly those using leveled FHE schemes with fixed circuit depth limitations, the invention incorporates sophisticated optimization techniques to maintain logarithmic multiplicative depth rather than linear depth. This is achieved through pre-computed dependency lists that specify optimal multiplication orders for aggregating path results. The dependency list computation is performed offline and depends only on the input bit-length μ, not on the actual input values. During online evaluation, the server follows the pre-computed dependency lists to perform multiplications in an order that minimizes multiplicative depth while maintaining correctness. This optimization reduces the multiplicative depth from μ to log μ at the cost of a modest increase in the total number of multiplications, resulting in substantial performance improvements for practical parameter sizes.

The invention supports several important extensions to address diverse operational requirements. For shared output scenarios, where the comparison result should be secret-shared between both parties rather than revealed entirely to one party, the server randomly selects between computing the greater-than-or-equal-to (GT) functionality or the less-than-or-equal-to (LT) functionality. The server generates a random share b_s and computes GT if b_s = 0 or LT if b_s = 1, then returns the appropriate encrypted result to the client. The client extracts its share b_c, and the parties can reconstruct the actual comparison result as b = b_c ⊕ b_s. This approach ensures that the server's computation pattern remains independent of the actual comparison result, preventing information leakage.

For less-than (LT) comparison operations, the invention defines an "inverse normal comparison tree" structure that mirrors the normal comparison tree but with reversed orientation and labeling rules. This inverse structure enables efficient computation of [x ≤ y] comparisons using the same fundamental evaluation procedures as the GT comparison, providing flexibility for different application requirements.

Special handling is provided for edge cases in AHE implementations, particularly when comparing against zero. When y = 0, the standard tree construction would produce μ + 1 leaf nodes, but the protocol is designed to return only μ ciphertexts to maintain consistency with other cases. The invention addresses this by having the server replace the first encrypted bit of x with a ciphertext of 0 and omitting the rightmost path during evaluation, ensuring correct results while maintaining the expected communication pattern.

Security analysis demonstrates that the protocol maintains semi-honest security under standard IND-CPA assumptions for the underlying homomorphic encryption schemes. In the semi-honest model, parties follow the protocol specification but may attempt to extract additional information from their protocol views. The security proof constructs simulators for both client and server that can generate views computationally indistinguishable from real protocol executions using only the parties' inputs and permitted outputs. For the client simulator in FHE implementations, the simulator generates random encryptions of the client's input bits and a random encryption of the comparison result. For AHE implementations, the simulator generates random encryptions of input bits and a set of ciphertexts where either all encrypt random values or exactly one (at random position) encrypts zero, matching the distribution observed in real executions. The server simulator generates random ciphertexts for all received and computed values, leveraging the IND-CPA security of the underlying encryption scheme to ensure indistinguishability.

Practical implementation considerations include careful selection of homomorphic encryption schemes based on application requirements. For AHE implementations, elliptic curve ElGamal encryption provides efficient performance with compact ciphertext sizes, while Paillier encryption offers alternative trade-offs in terms of computational complexity and security properties. For FHE implementations, schemes such as BGV provide the necessary functionality for complex homomorphic operations while supporting leveled evaluation to manage computational overhead.

Experimental evaluation demonstrates substantial performance improvements over existing state-of-the-art protocols. In the basic variant with only the client's input encrypted, the invention achieves a 45% reduction in running time compared to the original DGK protocol and approximately 10% improvement over Veugen's optimized DGK implementation. For the encrypted inputs variant where both parties' inputs are encrypted, the invention achieves more than 63% reduction in running time compared to existing approaches. These performance gains are particularly significant in applications requiring numerous comparison operations, such as privacy-preserving decision tree evaluation in machine learning, where the cumulative improvement scales with the number of comparison operations performed.

The invention's applicability extends across multiple domains requiring secure numerical comparisons. In privacy-preserving machine learning, particularly for decision tree classifiers, the protocol enables efficient evaluation of threshold comparisons without revealing either the model parameters or the input features. In secure benchmarking applications, companies can compare key performance indicators against competitors without disclosing actual performance metrics. In electronic auction systems, bidders can determine winning bids without revealing their actual bid amounts. In biometric authentication systems, the protocol supports threshold comparisons for similarity scoring while protecting sensitive biometric templates from disclosure.

The comprehensive nature of the invention, combining novel tree-based representation, optimized data structures, efficient evaluation procedures, and flexible operational modes, establishes a new state-of-the-art in secure integer comparison protocols. The single-round communication pattern, support for both FHE and AHE implementations, and substantial performance improvements make the invention particularly suitable for practical deployment in real-world privacy-preserving applications.
