## FIELD OF THE DISCLOSURE

Parsing constitutes a foundational operation in computer science, serving as the critical first step in numerous computational processes that involve structured data interpretation. The parsing problem arises whenever a sequence of symbols—typically characters or tokens—must be analyzed according to a formal syntactic specification to determine its structural validity and, often, to produce a corresponding internal representation such as an abstract syntax tree (AST). This problem is of paramount importance because virtually all software systems that process human-readable or machine-exchangeable formats must perform parsing at some stage. The significance of parsing extends across diverse domains: in compiler construction, source code must be parsed into executable representations; in web technologies, browsers parse HTML, CSS, JavaScript, JSON, and XML to render dynamic content; in network security, intrusion detection systems parse protocol messages to identify malicious payloads; and in telecommunications, signaling protocols are parsed to manage call routing and session establishment. Despite its ubiquity, conventional parsing approaches suffer from notable limitations that compromise reliability and correctness. Traditional parser generators, such as Yacc or ANTLR, rely on context-free grammars (CFGs) augmented with semantic actions but often produce parsers whose correctness cannot be formally guaranteed. These tools typically generate large, opaque parsing tables that resist manual verification, and their underlying algorithms may exhibit undefined behavior on ambiguous or malformed inputs. Moreover, the separation between lexical analysis (tokenization) and syntactic analysis in CFG-based systems introduces complexity and potential inconsistencies. Even widely used, mature parser generators contain documented bugs that undermine trust in their output. Consequently, there exists a pressing need for a parsing system that provides mathematically rigorous guarantees of correctness and termination while maintaining practical usability for real-world grammars.

## BACKGROUND OF THE DISCLOSURE

The parsing process traditionally involves two phases: lexical analysis, which segments an input character stream into meaningful tokens using regular expressions, and syntactic analysis, which applies grammar rules to these tokens to construct a hierarchical representation of the input structure. Parser generators automate this process by accepting a high-level grammar specification and producing executable parser code. Most classical parser generators are based on subclasses of context-free grammars (CFGs), such as LL(k) or LR(k) grammars, which impose restrictions to ensure deterministic parsing. These grammars are typically expressed in Backus-Naur Form (BNF) and augmented with semantic actions—code fragments executed during parsing to build ASTs or perform other computations. However, CFGs are inherently ambiguous for many practical languages, requiring additional disambiguation mechanisms, and their implementation often involves complex table-driven algorithms that obscure the relationship between grammar rules and parser behavior. Parsing Expression Grammars (PEGs) emerged as an alternative formalism that addresses several CFG limitations. Unlike CFGs, PEGs use prioritized choice operators that eliminate ambiguity by always selecting the first matching alternative, and they integrate lexical and syntactic analysis into a single phase. PEGs correspond directly to recursive descent parsers, making their implementation straightforward, and support unlimited lookahead through syntactic predicates. Nevertheless, PEGs introduce their own challenges: left-recursive grammar rules can cause non-terminating parsers, and ensuring total correctness—both functional correctness with respect to the grammar semantics and guaranteed termination on all inputs—remains difficult. Formal verification of parsers has been largely neglected; even in landmark projects like CompCert, a formally verified C compiler, the parser component is excluded from verification. Existing parser generators provide no mechanized proofs that their output parsers will terminate on all inputs or correctly implement the specified grammar semantics, leaving critical software components vulnerable to undetected errors.

## SUMMARY

The present invention introduces a novel parser creation system that overcomes the limitations of conventional approaches by providing mathematically rigorous guarantees of correctness and termination through formal verification within a proof assistant environment. The system comprises a grammar input module that accepts specifications in an extended Parsing Expression Grammar (XPEG) formalism, which augments standard PEG constructs with typed semantic actions for building structured representations of parsed inputs. A formalism module defines the mathematical foundations of XPEGs, including their syntax, typing discipline, and operational semantics, ensuring that all grammar specifications adhere to well-defined structural and type constraints. The semantic action module enables users to associate computational behaviors with grammar constructs, where semantic actions are expressed as functions in the host proof assistant language and automatically inherit termination guarantees from the proof assistant’s type system. A checking module performs static analysis on input grammars to verify their well-formedness, specifically ensuring the absence of direct or indirect left recursion that could lead to non-terminating parsers. This module implements a fixpoint computation over grammar expressions to determine whether all parsing constructs satisfy termination conditions derived from syntactic properties. A proof assistant module integrates the entire system within a formal verification framework, enabling machine-checked proofs that generated parsers are both correct with respect to XPEG semantics and terminating on all possible inputs. The security benefits of this approach are substantial: by guaranteeing parser termination and correctness, the invention eliminates entire classes of vulnerabilities that could be exploited through maliciously crafted inputs designed to trigger infinite loops or incorrect parsing behavior. The parser generator method systematically transforms well-formed XPEG specifications into executable parsers through a certified extraction process that preserves all formal guarantees, producing standalone parser implementations suitable for deployment in safety-critical applications.

## DETAILED DESCRIPTION OF ILLUSTRATIVE EMBODIMENTS

### 1. General Principles of An Embodiment of the Invention

The parser generator system of the present invention operates through a series of integrated modules that collectively ensure the production of certified correct and terminating parsers. The grammar input module receives specifications expressed in an extended Parsing Expression Grammar (XPEG) formalism, which builds upon standard PEG constructs by incorporating typed semantic values and actions. This module validates that all grammar components conform to the XPEG typing discipline, leveraging the host proof assistant’s type checker to prevent ill-formed specifications. The checking module performs comprehensive verification of grammar well-formedness through two complementary analyses: first, it verifies that the grammar structure itself is well-formed by ensuring all parsing expressions satisfy termination conditions, and second, it confirms that the grammar adheres to syntactic constraints that prevent non-terminating behavior. Specifically, the checking module for well-formed grammar implements a fixpoint algorithm that iteratively computes syntactic properties of parsing expressions—including whether they can succeed without consuming input ("0" property), succeed after consuming input (">0" property), or fail ("⊥" property)—and uses these properties to establish that all recursive calls in the grammar will eventually terminate. The semantic action module allows users to attach computational behaviors to grammar constructs through semantic actions expressed as functions in the proof assistant language; these actions automatically inherit termination guarantees from the proof assistant’s foundational logic. The formal module for parser generation defines the complete operational semantics of XPEGs and implements a certified interpreter that executes parsing according to these semantics. The advantages of this embodiment include guaranteed termination on all inputs, mathematical correctness with respect to the formal grammar specification, and seamless integration of lexical and syntactic analysis. The grammar formalism is extended with semantic actions that produce structured representations of parsed inputs, such as abstract syntax trees, while maintaining strong typing throughout the parsing process. Termination of the grammar is formally proved through the well-formedness analysis, which ensures that no left-recursive constructs—direct or indirect—can cause infinite loops during parsing. The system employs Parsing Expression Grammars (PEGs) as its foundational formalism, which provide unambiguous parsing through prioritized choice operators and support for syntactic predicates that enable unlimited lookahead. Parsing expressions in this system include standard constructs such as empty expressions (ǫ), terminal matches ([a]), character ranges ([a-z]), string literals (["s"]), non-terminal references (A), sequences (e₁; e₂), prioritized choices (e₁/e₂), and repetition operators (e*, e+), all extended with semantic value annotations. A parsing expression grammar (PEG) is formally defined as a tuple comprising terminal symbols, non-terminal symbols, a production mapping from non-terminals to parsing expressions, and a start symbol. As a concrete example, a simple grammar for mathematical expressions includes non-terminals for whitespace handling (ws), numeric literals (number), multiplicative terms (term), factors (factor), and additive expressions (expr), with productions that naturally handle operator precedence and associativity while incorporating whitespace consumption directly into the grammar rules.

### Example 1

A specific example of a simple grammar for mathematical expressions demonstrates the practical application of the invention’s principles. This grammar defines five non-terminals: ws for whitespace consumption, number for numeric literals, term for multiplicative expressions, factor for parenthesized expressions or numbers, and expr for additive expressions. The ws production consumes any sequence of space characters, enabling transparent whitespace handling throughout the grammar. The number production matches one or more digit characters and converts them to a numeric value through an associated semantic action. The term production handles multiplication by defining a right-associative structure that avoids left recursion, with semantic actions that compute the product of operands. The factor production matches either a parenthesized expression or a numeric literal, with appropriate semantic actions to preserve or evaluate the contained value. The expr production similarly defines right-associative addition to prevent left recursion, with semantic actions that sum the operands. This grammar naturally incorporates lexical analysis through the ws production, eliminating the need for separate tokenization phases, and produces evaluated numeric results as semantic values rather than merely recognizing valid expressions. The right-associative structure ensures termination by avoiding left-recursive calls, and all semantic actions are expressed as terminating functions within the proof assistant environment, guaranteeing that the complete parsing process will terminate on any input string.

### 2. Description of Some Embodiments

The system and method for creating a parser generator according to the present invention extends standard Parsing Expression Grammars (PEGs) with typed semantic actions to form Extended Parsing Expression Grammars (XPEGs). This extension introduces a family of parsing expression types Δα indexed by the type α of their associated semantic values, enabling compositional construction of structured parsing results. Default semantic actions are defined for all basic parsing constructs, providing sensible default behaviors while allowing user customization. A new coercion construction e[→]f is introduced to convert semantic values between different types using transformation functions f, facilitating flexible composition of parsing results. The type system includes fundamental types such as Type (the universe of types), True (a singleton type), char (machine characters), list α (lists of elements of type α), and product types α*β, providing sufficient expressiveness for practical parsing applications. Parsing expressions are extended to incorporate semantic values through the Δα family, where each parsing construct carries type information about its result value. An Extended Parsing Expression Grammar (EPEG) is formally defined as a tuple comprising terminal symbols, non-terminal symbols, a type assignment for non-terminals, a production mapping from non-terminals to typed parsing expressions, and a start symbol. Termination for PEGs is rigorously proved through syntactic analysis that establishes completeness—the property that parsing either succeeds or fails on all inputs. The expression set of a PEG G, denoted E(G), comprises all sub-expressions reachable from the start symbol, forming the basis for termination analysis. Three groups of syntactic properties are defined over parsing expressions: the "0" property (can succeed without consuming input), the ">0" property (can succeed after consuming input), and the "⊥" property (can fail). Inference rules systematically derive these properties through fixpoint computation, starting from empty property sets and iteratively applying derivation rules until stabilization. The semantics of these properties directly inform termination conditions: expressions that can succeed without consuming input require special handling to prevent infinite loops in repetition constructs. Well-formedness analysis for grammar G introduces a set WF of well-formed expressions, computed through another fixpoint iteration using derivation rules that ensure all recursive calls will eventually terminate. The grammar G is deemed well-formed if its complete expression set E(G) equals the computed well-formed set WF. Completeness of G—guaranteeing termination on all inputs—is formally proved for well-formed grammars through induction on input string length and well-formedness derivation depth. An example demonstrates extending a mathematical expression grammar with semantic actions that evaluate expressions to numeric values, showing how coercion operators handle type conversions between different parsing constructs. The interpretation of PEGs is formalized within the Coq proof assistant, providing a machine-checkable foundation for all subsequent developments. A formalization of PEGs in Coq establishes the complete theoretical framework, including syntax, semantics, and metatheoretical properties. A procedure for checking well-formedness implements the fixpoint computation described above, automatically verifying that input grammars satisfy termination conditions. A generic interpreter for parsing input strings is developed according to the formal semantics, with explicit handling of all parsing constructs and their semantic actions. Termination of the parsing process is formally proved by establishing a well-founded ordering on parser states that decreases with each recursive call. A certified parser interpreter is extracted from the Coq formalization through Coq’s program extraction mechanism, producing executable code that preserves all formal guarantees. An example of the certified parser interpreter demonstrates its application to practical parsing tasks, showing how it correctly processes valid inputs and terminates on invalid ones. A parser generator for PEGs is developed by extending the interpreter framework to accept grammar specifications as runtime inputs, though the current embodiment focuses on compile-time grammar specification. The parser generator is extracted from Coq to produce standalone executable code suitable for deployment. A specialized parser for PEGs themselves is developed to enable bootstrapping scenarios where grammars are specified textually rather than directly in Coq. A parser for the target language Q (semantic action language) is formally verified to ensure correct interpretation of user-provided semantic actions. The well-formedness of grammar G is checked through the automated procedure described above, providing a crucial safety guarantee before parsing begins. Termination of semantic actions is ensured by leveraging Coq’s foundational logic, where all functions are total by construction. A termination checker for language Q could be developed for alternative implementations, though the current embodiment relies on Coq’s built-in termination guarantees. The language Qfin is chosen as a subset of Q containing only terminating programs, though in practice the full Coq language suffices due to its logical consistency requirements. A standard library for parsing provides reusable components and utilities that simplify grammar development while maintaining formal guarantees. Total correctness of generated parsers is formally proved, establishing both functional correctness with respect to XPEG semantics and guaranteed termination on all inputs. The differences between TRX (the invention’s implementation) and other parser generators are substantial: unlike conventional tools that provide no correctness guarantees, TRX parsers are mathematically proven to be correct and terminating; unlike tools that separate lexical and syntactic analysis, TRX integrates both phases seamlessly; and unlike tools that produce opaque parsing tables, TRX’s behavior directly reflects the specified grammar structure.

### 3. Summary of Three Embodiments of the Invention

The present invention encompasses three distinct but related embodiments, each providing different levels of functionality while maintaining the core guarantees of correctness and termination. In all embodiments, PA denotes the proof assistant environment (specifically Coq), FPG represents the formal parsing grammar specification language, Q is the language for expressing semantic actions, and G denotes a specific grammar instance. The general approach involves specifying and developing parser interpreters or generators within the PA environment, then extracting certified executable code through PA’s program extraction capabilities, thereby preserving total correctness guarantees in the final implementation. The first embodiment provides a parser interpreter with semantic actions, where grammars are specified directly within PA at development time. FPG in this context is the XPEG formalism with its formal semantics defined in PA. A procedure for checking grammar feasibility (well-formedness) ensures termination before parsing begins. The parser interpreter executes parsing according to the formal XPEG semantics, with semantic actions expressed in Q (Coq’s programming language). Correctness of the parser interpreter is formally proved with respect to the XPEG operational semantics, and termination is established through the well-formedness analysis. The certified parser interpreter is extracted from PA to produce a standalone executable that maintains all formal guarantees. The second embodiment extends the first to provide a parser generator with semantic actions, enabling runtime grammar specification. FPG retains its formal semantics, and the grammar feasibility checking procedure remains essential for safety. Language Q is given formal semantics within PA, and a library of basic datatypes for Q is developed to support semantic action implementation. A formally correct parser for Q ensures that semantic actions are interpreted correctly, while a formally correct parser for FPG grammars enables processing of textual grammar specifications. A termination checker for semantic actions in Q could be implemented, though the current embodiment leverages PA’s built-in termination guarantees by restricting Q to PA’s total function space. The parser generator combines these components to produce parsers from FPG specifications, with formal proofs establishing both correctness and termination of the generated parsers. The certified parser generator is extracted from PA for practical deployment. The third embodiment enhances the first embodiment by adding parsing traces to support debugging and error reporting. FPG is extended with parsing tags that annotate grammar constructs with trace information. The parser interpreter is modified to record execution traces during parsing, capturing the sequence of parsing decisions and their outcomes. Correctness and termination of this enhanced interpreter are formally proved, ensuring that trace generation does not compromise the core guarantees while providing valuable diagnostic information for grammar developers.
