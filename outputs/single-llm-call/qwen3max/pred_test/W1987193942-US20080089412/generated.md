# DESCRIPTION

## FIELD OF THE INVENTION

The present invention relates generally to the field of digital video compression and, more specifically, to multi-view video coding and decoding. In particular, the invention provides methods, systems, and syntax elements for enabling efficient parallel decoding of multiple views in a multi-view video coding (MVC) framework, while maintaining high coding efficiency through inter-view prediction. The invention addresses challenges inherent in three-dimensional (3D) video applications—such as 3D television, free-viewpoint video, and immersive teleconferencing—where simultaneous decoding of multiple views is required to support functionalities like head-motion parallax and real-time rendering. The disclosed techniques facilitate scalable, low-latency, and memory-efficient decoding architectures that are compatible with existing video coding standards such as H.264/AVC and its scalable extension (SVC), while introducing novel signaling mechanisms to coordinate parallel processing across views without compromising compression performance.

## BACKGROUND OF THE INVENTION

Three-dimensional video communication and entertainment services have emerged as a transformative technology in consumer electronics, driven by advances in both acquisition and display systems. These services enable users to experience immersive visual content through stereoscopic or autostereoscopic displays, which render depth cues and support natural interaction with virtual or real-world scenes. A key enabler of such applications is multi-view video, which captures a scene from multiple camera perspectives and encodes these views into a single bitstream using multi-view video coding (MVC) techniques. MVC extends traditional monoview video codecs by exploiting not only temporal redundancies within a single view but also spatial and structural correlations across different views, thereby achieving significantly higher compression efficiency than independent coding of each view.

Modern 3D displays, particularly autostereoscopic types, often support head-motion parallax—a feature that allows viewers to perceive different perspectives of a scene as they move their heads laterally. This effect is realized by simultaneously decoding and displaying multiple views corresponding to adjacent camera positions. For instance, a display might render two or more views within a narrow angular range, switching between sets of views as the viewer’s position changes. To support this functionality, the decoder must process multiple views in real time, which imposes stringent computational and memory requirements. Without efficient parallelization, the decoding latency increases linearly with the number of views, making real-time playback impractical for systems with limited processing power or high view counts.

The MVC standard, developed as an extension of H.264/AVC, introduces inter-view prediction, wherein a picture in one view can use reconstructed pictures from other views at the same temporal instance as reference frames. While this greatly improves coding efficiency, it also creates strong dependencies between views: a picture in a dependent view cannot be decoded until the corresponding reference picture in the anchor view has been fully reconstructed. This sequential dependency fundamentally limits parallelism, as decoders must process views in a strict order, even when multiple processor cores or hardware accelerators are available. In extreme cases—such as displays supporting dozens or even hundreds of views—the decoder would need to operate many times faster than a single-view decoder, which is infeasible with current hardware.

Furthermore, conventional MVC decoding architectures suffer from inefficiencies in buffer management, random access, and stream adaptation. For example, in view-first coding structures, where all pictures of a single view are grouped together in the bitstream, the decoded picture buffer (DPB) must retain large numbers of pictures from earlier views until the last view in the group begins decoding, leading to excessive memory consumption. Additionally, extracting subsets of views for bandwidth-constrained clients or lower-complexity decoders requires deep parsing of the bitstream, which undermines the goal of lightweight adaptation at media gateways or network elements.

These challenges underscore the need for a new approach to MVC decoding that explicitly supports parallel processing of multiple views while preserving the benefits of inter-view prediction. Such an approach must include encoding constraints that limit cross-view dependencies to localized regions, signaling mechanisms to communicate these constraints to the decoder, and synchronization protocols to coordinate decoding operations across processing units. The present invention addresses these needs by introducing a structured framework for parallel-decodable slice coding, macroblock-level delay signaling, and adaptive reference area management, thereby enabling scalable, real-time 3D video delivery across diverse devices and network conditions.

## SUMMARY OF THE INVENTION

The present invention introduces a novel method for enabling parallel decoding of multiple views in a multi-view video coding (MVC) system, overcoming the sequential dependency limitations imposed by conventional inter-view prediction. At the core of the invention is a set of encoding constraints that restrict the spatial extent of inter-view reference areas, ensuring that any macroblock in a dependent view depends only on a well-defined, bounded region of the corresponding anchor view. This constraint is signaled to the decoder via a dedicated supplemental enhancement information (SEI) message—referred to herein as the *parallel decoding information SEI message*—which specifies parameters governing the allowable reference area and decoding delay between views.

Specifically, the invention defines syntax elements such as `pds_block_size` and `pds_initial_delay`, which indicate the granularity of parallel processing blocks and the number of macroblock rows that must be decoded in the anchor view before decoding can begin in the dependent view. By enforcing these constraints during encoding, the system ensures that decoding of different views can proceed concurrently on separate processing units, with only minimal synchronization overhead. For example, once the first two macroblock rows of View 0 are decoded, the decoder for View 1 may begin decoding its first row, while the View 0 decoder continues processing subsequent rows. This pipelined operation dramatically reduces total decoding time without sacrificing the compression gains of inter-view prediction.

The invention further introduces a `parallelly_decodable_slice_flag` to indicate whether a given slice adheres to the parallel decoding constraints, and a `pds_parameters_present_flag` to signal the presence of parallel decoding parameters in the bitstream. Additionally, a `fixed_pds_for_all_sequence_flag` allows the encoder to apply uniform parallel decoding settings across an entire coded video sequence, simplifying decoder implementation. The available reference area for inter-view prediction is mathematically defined based on the current macroblock position and the signaled delay parameters, ensuring that motion vectors never reference pixels outside the decoded region of the anchor view.

Advantages of the invention include near-linear scalability in decoding throughput with the number of processor cores, reduced end-to-end latency for 3D video rendering, and compatibility with existing MVC and H.264/AVC infrastructure. Coding efficiency is preserved—experimental results show less than 0.08 dB loss compared to unconstrained MVC—and significant gains over simulcast approaches (up to 0.9 dB). The invention also facilitates adaptive streaming, as media gateways can extract view subsets without violating decoding dependencies, and supports backward compatibility by allowing non-parallel-decodable streams to coexist with enhanced ones.

## DETAILED DESCRIPTION OF VARIOUS EMBODIMENTS

The present invention is implemented within a multimedia communications system designed for multi-view video delivery. The system includes a data source comprising multiple synchronized cameras capturing a scene from distinct viewpoints. These raw video signals are fed into an MVC encoder, which compresses the multi-view content into a single bitstream using inter-view prediction, temporal scalability, and the parallel decoding constraints disclosed herein. The encoded bitstream is stored in a file or transmitted over a network via a sender component, which may include a media gateway or MANE (Media-Aware Network Element) capable of adapting the stream based on client capabilities or network conditions.

The communication protocol stack supports various transmission technologies, including broadcast, multicast, and unicast over IP networks, cellular systems, or satellite links. Communication devices range from set-top boxes and smart TVs to mobile handsets and head-mounted displays. At the receiver, an MVC decoder parses the bitstream, extracts relevant views, and reconstructs the video using parallel processing units. The renderer then composes the decoded views into a 3D output, leveraging depth information if available, and supports features such as head-motion parallax and view switching.

Scalability is a fundamental design principle. The system supports view scalability—allowing clients to decode only a subset of views—and temporal scalability, enabling frame rate adaptation. Transmission technologies include DVB-H, LTE, Wi-Fi, and wired broadband, while communication devices encompass everything from high-end 3D displays to legacy 2D decoders that can extract the base view for backward compatibility.

Frames are represented as sequences of macroblocks, each potentially referencing regions in other views. The invention enables parallel decoding of views by imposing structured constraints on these references. For two views, View 0 (anchor) and View 1 (dependent), the decoding process begins simultaneously on separate processors. However, the View 1 decoder enters a WAIT state until the View 0 decoder completes decoding of a sufficient number of macroblock rows, as dictated by the `pds_initial_delay` parameter. Once notified, View 1 proceeds, and both decoders operate in parallel with a fixed row offset.

This notification process is implicit in the decoding logic: the decoder tracks the highest decoded row in the anchor view and permits decoding in the dependent view only when the required reference area is available. The parallel implementation minimizes idle time and balances workload across cores. Delay and synchronization overhead are kept low by aligning block boundaries with macroblock rows and using integer-based delay signaling.

To enable this, the encoder signals macroblock delay parameters via SEI messages. Key syntax elements include `pds_block_size`, which defines the vertical height of processing blocks (e.g., 16 pixels), and `pds_initial_delay`, indicating how many blocks of the anchor view must precede decoding in the dependent view. The `available_reference_area` is computed as a function of the current macroblock row index and these parameters, ensuring that motion compensation never accesses undecoded pixels.

The `pds_parameters_present_flag` indicates whether parallel decoding parameters are active in the current sequence. If `fixed_pds_for_all_sequence_flag` is set, the same parameters apply throughout. The `parallelly_decodable_slice_flag` marks individual slices as compliant with the parallel decoding rules.

Adaptive deblocking and sub-pixel interpolation are modified to respect reference availability. A sliding deblocking approach filters macroblock boundaries only after neighboring blocks in both views are decoded. Sub-pixel interpolation uses padding or limiting strategies when reference pixels are unavailable, though this may slightly degrade coding efficiency. To mitigate this, the encoder arranges view dependencies to minimize cross-view references at high temporal levels, or modifies the original picture layout using slice groups and a modified raster scan order that aligns with parallel processing blocks.

Signaling is achieved through SEI messages embedded in the NAL unit stream. The SEI NAL unit carries user data and standardized messages, including the parallel decoding parameters. The bitstream follows the byte-stream format of H.264/AVC, with NAL units containing headers that include view ID, temporal ID, and inter-view flags.

Entropy coding (CAVLC or CABAC) and motion vector coding are adapted to the parallel context. Motion vectors are constrained to lie within the available reference area, and their horizontal and vertical components are coded either jointly or separately using variable-length codes optimized for the restricted search range.

The invention can be implemented in an electronic device comprising a processor, memory, video decoder, and network interface. Alternatively, it may be embodied as a program product on a computer-readable medium, executable by general-purpose or specialized hardware. Software implementations may include rule-based logic for buffer management, database searching for reference picture selection, correlation steps for motion estimation, comparison steps for mode decision, and decision steps for slice partitioning.

Modifications and variations are possible, including combining features from different embodiments—for instance, integrating parallel decoding with view scalability SEI messages or active view information signaling. The core innovation remains the structured coordination of multi-view decoding through explicit delay and reference area constraints, enabling real-time 3D video on practical hardware.
