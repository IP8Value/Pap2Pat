# DESCRIPTION

## BACKGROUND

Conversational search represents a transformative evolution in information retrieval systems, moving beyond the rigid constraints of traditional one-shot query-response interactions toward dynamic, multi-turn dialogues between users and intelligent agents. In conventional search paradigms, users formulate static queries—often keyword-based—and receive ranked lists of documents without further interaction. This approach assumes that the user’s information need is fully and accurately captured in a single expression, which is rarely the case in complex or ambiguous scenarios. As a result, users frequently struggle to articulate precise intents, leading to suboptimal retrieval outcomes, especially when dealing with exploratory, ill-defined, or multi-faceted information needs.

The conversational search paradigm addresses these limitations by enabling mixed-initiative dialogue, wherein both the user and the system actively contribute to refining the search process. In this model, the system not only responds to user queries but may also proactively ask clarification questions to disambiguate intent, narrow scope, or uncover latent requirements. Such clarification questions serve as critical signals that guide subsequent retrieval and response generation, significantly improving the relevance and utility of returned information. This interactive mechanism mirrors natural human conversation, where clarification is routinely used to resolve ambiguity and align understanding.

Despite its promise, implementing effective conversational search systems presents substantial technical challenges. Existing approaches to clarification question handling fall into two broad categories: generation and selection. Generation methods synthesize new questions using rule-based templates or neural language models, offering flexibility but often suffering from fluency, coherence, or factual grounding issues. Selection methods, by contrast, choose from a pre-existing pool of candidate clarification questions—typically mined from historical query logs or curated datasets—ensuring linguistic quality and domain relevance at the cost of reduced novelty. While both paradigms have merit, the selection approach provides a more controlled, reliable framework for deployment in real-world applications, particularly where factual accuracy and consistency are paramount.

Prior art in clarification question selection has largely focused on modeling the relationship between user queries and candidate questions, often leveraging transformer-based architectures such as BERT or RoBERTa to compute semantic similarity. However, these methods typically operate in isolation from the underlying knowledge corpus, ignoring the rich contextual signals embedded in retrieved documents or passages. For instance, some systems re-rank candidate questions based on document retrieval scores obtained when using the question as a query, but they do not directly incorporate passage-level content into the ranking decision. Other approaches rely on information-theoretic measures like expected value of perfect information, which require assumptions about user response distributions and lack grounding in actual document evidence. Consequently, existing solutions fail to fully exploit the synergistic relationship between conversation context, retrieved passages, and clarification questions—limiting their ability to select questions that are both contextually appropriate and content-informed.

## SUMMARY

The present invention introduces a computer-implemented method for automatically selecting clarification questions in a conversational search system. The method begins by receiving a search conversation comprising a sequence of utterances between a user and an agent, up to but not including a clarification-question turn. From this conversation context, the system retrieves relevant text passages from a background document corpus using a multi-stage passage retrieval process that incorporates utterance-aware term weighting. Concurrently, the system retrieves a set of candidate clarification questions associated with each retrieved passage from a pre-indexed clarification question pool.

To rank these candidates, the invention employs two deep learning models trained specifically for clarification question selection. A first model outputs a score representing the strength of association between the conversation context and each candidate clarification question, independent of passage content. A second model outputs a score reflecting the joint association among the conversation context, a specific text passage, and the candidate clarification question. These two scores are fused—using a combinatorial fusion strategy such as CombSUM—to produce a final ranking score for each candidate. The highest-ranking candidate clarification question is then provided to the user to solicit additional information and refine the search intent.

In addition to the method, the invention encompasses a system embodiment comprising one or more processors and memory storing instructions that, when executed, cause the system to perform the aforementioned operations. The system includes a conversational interface module, a document index, a clarification question index, a passage retrieval module, a clarification-question retrieval module, and a clarification-question selection module housing the two deep learning models. Furthermore, the invention includes a computer program product comprising a non-transitory computer-readable storage medium with program code executable by a computing device to carry out the method steps.

The deep learning models are trained using a triplet network architecture adapted for BERT-based fine-tuning. Training data is derived from human-to-human (H2H) conversations grounded in solution documents, where clarification questions and their corresponding answers are labeled. During training, the first model learns from triplets consisting of a conversation context, a positive clarification question, and a negative (randomly sampled) clarification question. The second model learns from triplets that additionally include a relevant passage retrieved from the solution document associated with the conversation. This dual-model architecture enables the system to leverage both conversation-level semantics and passage-level evidentiary support when selecting clarification questions, resulting in more accurate and contextually grounded interactions.

## DETAILED DESCRIPTION

The present invention provides a computer-implemented method for the automatic selection of clarification questions during a conversational search session. The method is designed to operate within a content-grounded conversational search framework, wherein each conversation culminates in the retrieval of one or more solution documents from a background corpus. The system, computer program product, and associated modules are engineered to dynamically interpret user intent through dialogue history and select the most informative clarification question to resolve ambiguity and improve downstream retrieval performance.

Central to the invention is the use of two deep learning models that collaboratively rank candidate clarification questions. The first model, referred to herein as BERT-C-cq, is configured to output a numerical score denoting the strength of semantic association between a given conversation context and a candidate clarification question. This model operates solely on the dialogue history and the candidate question, capturing patterns of linguistic compatibility and pragmatic relevance without reference to external content. The second model, BERT-C-P-cq, extends this analysis by incorporating a retrieved text passage into the input representation. It outputs a score reflecting the triadic relationship among the conversation context, the passage, and the candidate question, thereby grounding the selection process in evidentiary content from the knowledge base.

The fusion of scores from both models is performed using a linear combination or probabilistic fusion technique such as CombSUM, which sums normalized scores from each model to produce a final ranking metric. This fusion strategy exploits complementary signals: the first model excels in scenarios where passage retrieval is noisy or irrelevant, while the second model leverages passage content to identify questions that directly probe document-supported interpretations of user intent.

Candidate clarification questions are retrieved from a pre-constructed index populated with questions mined from historical query logs, customer support transcripts, or crowdsourced datasets. For each passage retrieved in response to the conversation context, the system constructs a composite query comprising the passage text and the full conversation history, then executes this query against the clarification question index to obtain a list of passage-associated candidates.

Training of the deep learning models occurs within a dedicated training system comprising data ingestion, labeling, and model optimization components. Human-to-human (H2H) conversations—each ending with a solution document—are ingested as raw training data. Clarification questions within agent utterances are labeled using a combination of heuristic rules (e.g., presence of question words, syntactic parse structures) and document-relevance filtering: only questions whose answers retrieve the conversation’s solution document within the top-k results are retained as valid positives. Text passages relevant to each H2H conversation are extracted using a sliding window over the solution document’s content, with passage relevance approximated under a weak supervision assumption that all passages in a relevant document are themselves relevant.

Two distinct training sets are constructed. The first comprises triplets of (conversation context, positive clarification question, negative clarification question) for training BERT-C-cq. The second comprises triplets of (concatenated conversation context and passage, positive clarification question, negative clarification question) for training BERT-C-P-cq. Both models are fine-tuned using a triplet loss function that minimizes the distance between positive pairs while maximizing separation from negative pairs in the embedding space.

During runtime operation, the conversational search system receives a live search conversation, retrieves top-m solution documents using a BM25-based retriever with utterance-biased term weighting, and extracts candidate text passages via a sliding window of fixed character length (e.g., 512 characters). Each passage is assigned an initial score based on term coverage of the conversation utterances, computed using global IDF and scaled TF metrics, then combined with its parent document’s score via a weighted sum (e.g., λ = 0.5). The top-r passages are selected for clarification question retrieval.

For each selected passage, candidate clarification questions are fetched from the clarification index. These candidates are then ranked using one or both trained models. When both models are used, their individual scores are fused to yield a final ranking. The top-ranking candidate clarification question is presented to the user. Optionally, multiple top-ranking candidates may be displayed to allow user choice.

The system is implemented using standard hardware and software components, including one or more CPUs or GPUs, volatile and non-volatile memory, and an operating system such as Linux or Windows. Software modules are written in Python or Java, leveraging libraries such as PyTorch and Hugging Face Transformers for BERT model execution. The document and clarification indices are built using Apache Lucene with English analyzers and BM25 similarity. All instructions are stored on a computer-readable storage medium—such as a hard disk, SSD, or cloud storage—and executed by a computing device to implement the disclosed functionality.

### Experimental Results

The efficacy of the proposed method—referred to as Method 200 (single-model variants) and Method 300 (fused dual-model variant)—was evaluated on two distinct datasets: ClariQ and Support. The ClariQ dataset, developed for the Clarifying Questions for Open-Domain Dialogue Systems challenge, comprises high-quality, crowdsourced three-turn conversations in an open-domain web search setting. Each conversation includes an initial user query, a system clarification question, and a user response, with associated solution documents drawn from a 2.7-million-document corpus. In contrast, the Support dataset consists of noisy, real-world human-to-human technical support logs from an enterprise customer service platform, featuring chit-chat, fragmented utterances, and implicit clarification patterns.

Key differences between the datasets necessitated tailored preprocessing. For ClariQ, document retrieval relied solely on the document text field due to sparse anchor text coverage. For Support, both text and anchor fields were used, as most documents had associated training conversations providing rich anchor metadata. Passage retrieval employed a 512-character sliding window with overlap, and hyperparameters were set to λ = 0.5 for score fusion and µ = 2000 for Dirichlet smoothing in the Fixed-Point reranking algorithm.

Deep learning models were implemented using the PyTorch Hugging Face BERT-base-uncased architecture (12 layers, 768 hidden units). The BERT-C-cq model used a maximum sequence length of 256 tokens, while BERT-C-P-cq used 384 tokens to accommodate passage concatenation. Models were fine-tuned for three epochs with a learning rate of 2e-5 on 32GB V100 GPUs.

Initial candidate clarification questions were retrieved in bulk—up to 1000 per passage—using Lucene-based indexing. Evaluation followed the ClariQ challenge protocol, using Recall@30 (R@30) as the primary metric.

Results on development sets demonstrated significant improvements over the IR-Base retrieval baseline. On the Support dataset, BERT-C-cq achieved R@30 = 0.538 versus IR-Base’s 0.294—a 82% relative gain. On ClariQ, BERT-C-cq scored R@30 = 0.770 compared to IR-Base’s 0.650. Both BERT models performed similarly, but their fusion (BERT-fusion) yielded consistent gains: +2.5% on ClariQ (R@30 = 0.791) and +3.1% on Support. This improvement stems from complementary signal integration; for example, on the query “all men are created equal,” BERT-C-P-cq identified nine correct clarifications in the top-30 by leveraging passage content about Thomas Jefferson and the Declaration of Independence, whereas BERT-C-cq found only three.

Official ClariQ test set results placed BERT-fusion fourth overall and second among independent teams. Notably, the top-performing system exploited dataset-specific leakage by prioritizing test-set questions, an approach invalid in general settings. The present invention treats all clarification questions equally, ensuring robustness across domains.
