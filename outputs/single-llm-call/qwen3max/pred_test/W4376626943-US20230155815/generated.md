# DESCRIPTION

## TECHNICAL FIELD

The present invention relates generally to the field of cryptography and secure computation, and more specifically to methods and systems for performing secure integer comparison in a multiparty computation setting. The invention provides novel protocols that enable two parties—typically referred to as a client and a server—to determine whether one party’s private integer is greater than or equal to another party’s private integer, without either party revealing their respective inputs beyond what is strictly necessary to obtain the comparison result. The protocols leverage homomorphic encryption schemes, including both fully homomorphic encryption (FHE) and additively homomorphic encryption (AHE), to achieve this goal in a non-interactive, single-round communication model. The invention is particularly applicable in privacy-preserving applications such as secure auctions, enterprise benchmarking, biometric authentication, and machine learning inference over encrypted data, where the protection of sensitive numerical inputs is paramount.

## RELATED ART

Multiparty computation (MPC) is a foundational cryptographic paradigm that enables multiple parties to jointly compute a function over their private inputs while preserving the confidentiality of those inputs. A canonical problem in this domain is Yao's Millionaires' problem, first introduced by Andrew Yao in 1982, which poses the following question: two wealthy individuals wish to determine who is richer without disclosing their actual net worths. Formally, given two parties holding private integers \(x\) and \(y\), the objective is to securely compute the Boolean predicate \([x \geq y]\)—returning 1 if \(x\) is greater than or equal to \(y\), and 0 otherwise—without leaking any additional information about \(x\) or \(y\). This problem has since become a cornerstone of secure computation and has inspired numerous protocols across different cryptographic models.

Over the decades, various approaches to secure integer comparison have been proposed. Early solutions relied on garbled circuits, as demonstrated by Kolesnikov et al., which are effective but often incur high communication and computational overhead. Another influential line of work centers on homomorphic encryption. The Damgård–Geisler–Kratz (DGK) protocol, introduced in 2007, utilizes additively homomorphic encryption (AHE) to perform comparison with relatively low complexity, though it requires multiple rounds of interaction and several modular inversions and encryptions per bit. Subsequent optimizations by Veugen and Joye–Salehi improved efficiency but still retained multi-round structures or introduced additional assumptions. More recent protocols based on the arithmetic black-box (ABB) model or secret sharing offer unconditional security and support for more than two parties, yet they typically demand an offline preprocessing phase and multiple communication rounds, limiting their practicality in latency-sensitive settings.

Fully homomorphic encryption (FHE)-based approaches, such as those by Cheon et al., enable arbitrary computations on encrypted data and have been adapted for integer comparison. These methods can operate in a single round but often suffer from high multiplicative depth or require scheme-specific optimizations (e.g., tailored to BGV or BFV). Moreover, many existing protocols assume specific encryption schemes or cannot handle scenarios where both inputs are encrypted or where the output must be shared between parties. A critical limitation across much of the prior art is the lack of a unified, non-interactive framework that supports both FHE and AHE instantiations, accommodates encrypted inputs, and scales efficiently with input bit-length while maintaining minimal communication and computational overhead. The present invention addresses these gaps by introducing a novel binary tree–based protocol that is both general and highly optimized.

## SUMMARY

The present invention introduces a new method for secure integer comparison between two parties using homomorphic encryption, implemented through a non-interactive, single-round protocol. The core innovation lies in representing the server’s private integer as a specially structured binary tree—referred to as a normal comparison binary tree—and enabling the client to evaluate this tree on its own encrypted input without revealing either party’s data.

In a first embodiment, the server holds its input \(y\) in plaintext and constructs a pruned binary tree that encodes the comparison logic for \([x \geq y]\). The client encrypts its input \(x\) using a homomorphic encryption scheme and sends the ciphertext to the server. The server evaluates the encrypted input against the tree structure, aggregates path-specific decision bits, and returns an encrypted result to the client, which then decrypts to obtain the comparison bit. This embodiment achieves significant performance gains over the DGK protocol and its variants, reducing running time by up to 45% compared to the original and 10% compared to Veugen’s optimization.

In a second embodiment, both inputs \(x\) and \(y\) are encrypted under the client’s public key. The server constructs a “normal comparison binary tree” whose structure is independent of the actual value of \(y\), thereby preventing leakage of \(y\)’s bit pattern. Edge labels are derived homomorphically from the encrypted bits of \(y\), and the client’s encrypted input is evaluated against this generalized tree. This variant supports fully encrypted computation and reduces running time by more than 63% compared to prior encrypted-input protocols.

A third embodiment extends the protocol to support shared output, where the comparison bit is split into random shares held by both parties. The server randomly chooses to compute either \([x \geq y]\) or \([x < y]\), derives its share accordingly, and the client computes its complementary share upon decryption. Reconstruction yields the true comparison result while preserving privacy.

The invention leverages homomorphic encryption—both FHE and AHE—to enable computation on encrypted data without decryption. In FHE mode, path aggregation uses homomorphic multiplication; in AHE mode, it uses homomorphic addition combined with randomized padding and permutation to ensure semantic security. A key advantage of the protocol is its non-interactive nature: only one message flows from client to server and one response returns, minimizing latency and simplifying deployment in real-world systems.

## DETAILED DESCRIPTION

Secure integer comparison is a fundamental operation in privacy-preserving computation, enabling applications ranging from secure auctions to encrypted machine learning. The present invention provides a robust, efficient, and flexible solution to this problem through a novel protocol based on binary tree evaluation under homomorphic encryption.

The protocol begins with the client generating a key pair for a homomorphic encryption scheme—either fully homomorphic (FHE) or additively homomorphic (AHE)—and transmitting the public and evaluation keys to the server. For each comparison instance, the client encrypts its \(\mu\)-bit integer input \(x\) and sends the ciphertext vector to the server.

The server then constructs a binary tree representation of its own input \(y\). In the basic variant, where \(y\) is known in plaintext, the server builds a pruned comparison tree: starting from the root, it traverses according to the bits of \(y\), inserting leaf nodes labeled 0 or 1 to the left or right at each level to encode all integers greater than or equal to \(y\). This results in a tree with exactly \(\mu + 1\) leaves and \(\mu\) inner nodes. In the encrypted-input variant, the server constructs a “normal comparison binary tree,” whose topology is fixed for a given \(\mu\) and independent of \(y\)’s value. The leftmost path is labeled with the (encrypted) bits of \(y\), and each inner node’s right child is a leaf labeled according to a function \(F_\beta(b)\), where \(\beta = 1\) for FHE and \(\beta = 0\) for AHE, ensuring consistent semantics across encryption types.

The goal of the computation is for the server to evaluate the client’s encrypted input \(x\) on this tree without learning \(x\) and without revealing \(y\) beyond the comparison result. This is achieved by computing, at each level, a homomorphic comparison between the client’s encrypted bit and the edge label (plaintext or encrypted). For FHE, equality is tested via XNOR; for AHE, inequality is tested via XOR, with adjustments for negative values in the encrypted case.

A distinguishing feature of the protocol is its non-interactive design: after the initial key exchange (a one-time setup), each comparison requires only one round of communication—client to server with encrypted \(x\), server to client with encrypted result. This contrasts sharply with multi-round protocols like DGK and enhances suitability for high-latency or bandwidth-constrained environments.

The output expressiveness is carefully controlled: in FHE mode, the server returns a single encrypted bit; in AHE mode, it returns a list of \(\mu\) ciphertexts, at most one of which decrypts to zero (indicating \(x \geq y\)), with the rest randomized and permuted to prevent structural leakage. The server’s input may be in plaintext or encrypted; in the latter case, the normal tree construction ensures no information about \(y\) is exposed through the tree shape.

Evaluation may be performed by a third-party server, provided it possesses the client’s public key and, if needed, the evaluation key. This enables outsourced secure computation in cloud settings. The protocol satisfies statutory requirements for patentability, including novelty, non-obviousness, and utility, as it solves a long-standing problem in MPC with measurable performance improvements.

The claimed subject matter encompasses methods, systems, and computer-readable media implementing the described protocol. Minor variations—such as alternative tree traversals, different homomorphic schemes, or integration into larger workflows—are considered within the scope of the invention.

Accompanying drawings illustrate exemplary binary trees, array representations, and evaluation flows. Specific embodiments include implementations using Paillier, Elliptic Curve ElGamal (for AHE), and BGV/BFV (for FHE).

The homomorphic encryption scheme includes four core algorithms: key generation, encryption, evaluation, and decryption. Key generation takes a security parameter \(\lambda\) and outputs public, private, and evaluation keys. Encryption maps a plaintext to a ciphertext under the public key. The evaluation algorithm homomorphically applies functions (e.g., addition, multiplication) to ciphertexts using the evaluation key. Decryption recovers the plaintext using the private key. The scheme must satisfy IND-CPA security and correctness: decrypting an encrypted message or an evaluated ciphertext yields the expected plaintext.

FHE supports both addition and multiplication, enabling arbitrary circuit evaluation. Addition is implemented as homomorphic addition of ciphertexts; constant addition uses MulCons. Multiplication combines ciphertexts homomorphically; constant multiplication scales a ciphertext by a plaintext constant. Somewhat homomorphic (SHE) and leveled FHE schemes support bounded-depth circuits without bootstrapping, offering practical efficiency.

AHE schemes, such as Paillier or Elliptic Curve ElGamal, support only addition but are highly efficient. They enable XOR via subtraction (\(a \oplus b = a - b\)) and NOT via \(1 - b\), though care is taken to handle negative results in the encrypted-input case.

Protocol 100 outlines the basic client-server interaction: client encrypts \(x\), server builds tree from plaintext \(y\), evaluates paths, aggregates results, and returns encrypted output. Binary tree construction follows the bit decomposition of \(y\), pruning redundant subtrees. Evaluation computes decision bits per path, aggregates them (via multiplication in FHE, addition in AHE), and combines with leaf labels.

Method 200 details the encrypted-input variant: client sends encrypted \(x\) and \(y\); server uses Algorithm 7 to build a normal comparison tree from encrypted \(y\); evaluation proceeds with homomorphic equality/inequality tests; result is randomized and permuted in AHE mode.

Method 300 refines tree construction: for AHE, only paths yielding zero are retained; for FHE, full pruning is applied. The normal tree is built with leftmost path labeled by \(y\)’s bits; inner nodes have right-child leaves labeled \(F_\beta(b)\). Inverse trees support less-than comparisons.

Evaluation involves computing decision bits, aggregating along paths, and summing weighted leaf contributions. In FHE, the final result is a single encrypted bit. In AHE, the client iteratively decrypts a list of ciphertexts to check for a zero.

For certain use cases, the protocol is modified: when \(y = 0\) in AHE mode, the rightmost path is omitted; for shared output, the server flips the comparison direction randomly and returns a share.

An optimized implementation replaces the tree with a \( (\mu+1) \times 3 \) array, storing bit equalities, negations, and leaf labels. Evaluation proceeds row-wise, with precomputed dependency lists enabling logarithmic multiplicative depth in leveled FHE. This avoids recursive product trees and simplifies implementation.

Applications include secure auctions (determining highest bidder), enterprise benchmarking (ranking KPIs), and private decision tree evaluation in machine learning. The protocol integrates into larger systems, with outputs fed into subsequent secure computations.

The hardware platform comprises a central processing unit, random-access memory, graphics card, network interface, and system bus, executing program instructions stored in memory to perform the protocol steps.
