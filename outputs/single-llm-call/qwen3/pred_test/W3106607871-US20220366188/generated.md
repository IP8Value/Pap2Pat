## BACKGROUND

- relate to semantic role labeling

Semantic role labeling is a foundational task in natural language understanding that seeks to identify and classify the semantic roles played by constituents within a sentence relative to a predicate. These roles, often grounded in frame semantics, capture the underlying thematic relationships such as agent, patient, instrument, location, or temporal modifier that connect arguments to their governing verbs or predicates. The task is critical for enabling machines to move beyond syntactic parsing and achieve deeper semantic comprehension, which is essential for applications including question answering, information extraction, machine translation, and dialogue systems. Traditional approaches to semantic role labeling relied heavily on handcrafted linguistic features and syntactic parsers to identify predicate-argument structures. However, such methods were brittle, domain-dependent, and struggled with the variability of natural language. With the advent of deep learning, end-to-end neural architectures have largely replaced rule-based systems, achieving state-of-the-art performance by learning dense, context-sensitive representations of words and their relationships. Despite these advances, current models remain fundamentally limited in their ability to generalize from sparse or low-frequency training examples, particularly when encountering rare predicates or unusual argument structures that deviate from common patterns observed during training. This limitation arises because deep neural networks, while powerful in capturing statistical regularities, tend to overfit to dominant distributions in the training data and lack mechanisms to effectively leverage contextual memory or instance-specific evidence at inference time. Consequently, even highly optimized models exhibit significant performance degradation on out-of-domain text, low-frequency predicates, and edge-case constructions that are semantically valid but statistically rare. The inability to adapt dynamically to such exceptions undermines the robustness and reliability of semantic role labeling systems in real-world deployment scenarios where linguistic diversity and unpredictability are the norm rather than the exception.

## SUMMARY

- introduce embodiments

Embodiments of the present invention introduce a novel computational framework for semantic role labeling that dynamically enhances the predictive capacity of deep learning models by integrating a parameterized neighborhood memory adaptation mechanism. This framework enables a base semantic role labeling model to leverage stored activation patterns from previously seen training examples during inference, thereby improving its ability to handle low-frequency predicates and rare argument structures without requiring additional labeled data or architectural complexity. The invention operates by first constructing a memory library of token-level activation vectors derived from a trained base model, then computing a compact, learnable representation of each token’s nearest neighbors in that memory, and finally retraining the classification layers of the base model to optimally combine these neighborhood representations with the original token embeddings. This process allows the system to effectively “remember” and adapt to contextual patterns that were underrepresented during initial training, thereby correcting systematic errors that conventional models fail to resolve. The resulting system is fully automated, computationally efficient, and compatible with any deep learning architecture used for sequence labeling, including those based on LSTMs, Transformers, or hybrid encoders.

- describe system components

The system comprises four primary components: a receiver component, a library component, a parametric component, and an execution component. The receiver component ingests raw input sentences and preprocesses them into sequences of tokens, each associated with a binary predicate indicator. The library component stores a collection of activation vectors generated by the final hidden layer of a pre-trained semantic role labeling model during its initial training phase, indexed by token identity and context. The parametric component computes a learnable, weighted combination of the k-nearest neighbors for each token in the input sentence, using a set of trainable neighborhood parameters that encode the relative relevance of each neighbor’s activation vector. The execution component integrates these neighborhood parametric representations into the classification pipeline, feeds them through the frozen encoder layers of the base model, and applies the retrained labeler to produce final semantic role predictions. All components operate within a unified computational graph that supports end-to-end backpropagation, enabling continuous refinement of the neighborhood parameters during retraining.

- outline system operation

The system operates in two distinct phases: a library generation phase and a parameterized neighborhood adaptation phase. In the first phase, a base semantic role labeling model is trained on a labeled corpus using standard supervised learning techniques. Once trained, the model processes each token in the training set, and the activation vector from its final hidden layer is recorded alongside the token’s identity and true semantic role label, forming an indexed memory library. In the second phase, the base model’s encoder and embedding layers are frozen, and a new set of learnable neighborhood parameters is initialized. For each token in the training set, the system identifies its k-nearest neighbors in the library using Euclidean distance between activation vectors. A parametric representation is then computed by combining the activation vectors of these neighbors using the learnable parameters, producing a compact, context-sensitive neighborhood embedding. This embedding replaces or supplements the original token representation and is fed into the classification layers, which are retrained using standard cross-entropy loss. After retraining, the system is deployed by computing the neighborhood parametric representation for each token in a new input sentence using the same library and parameters, then generating semantic role labels through the retrained labeler. The entire process is fully automated, requires no manual feature engineering, and adapts dynamically to linguistic variation through learned neighborhood relationships.

## DETAILED DESCRIPTION

- introduce semantic role labeling

Semantic role labeling is the computational task of identifying the semantic roles that arguments play with respect to a predicate in a sentence, thereby revealing the underlying thematic structure of the utterance. Unlike syntactic roles, which are determined by grammatical function such as subject or object, semantic roles reflect the meaning-based relationships such as who performed an action, what was affected, where it occurred, or when it happened. These roles are typically defined within a frame-based semantic ontology such as PropBank or FrameNet, which catalogues predicate-specific role sets. For example, the verb “give” may have roles such as ARG0 (the giver), ARG1 (the thing given), and ARG2 (the recipient). The goal of semantic role labeling is to assign each argument in a sentence one or more of these roles, enabling machines to interpret the meaning of the sentence beyond its surface form. This task is essential for any application requiring deep language understanding, including automated summarization, knowledge base population, and conversational agents.

- define semantic role labeling

Semantic role labeling is formally defined as the process of mapping a sentence and a designated predicate within it to a set of argument-role pairs, where each argument is a contiguous span of tokens or a dependency-linked node, and each role is drawn from a predefined set of semantic roles associated with that predicate. The output of semantic role labeling is a structured annotation over the sentence that specifies, for each argument, its syntactic boundaries and its semantic role label. This task is typically decomposed into subtasks: predicate identification, predicate sense disambiguation, argument detection, and role classification. In the embodiments described herein, the predicate is assumed to be given, and the focus is on the latter two subtasks, which are reformulated as a sequence tagging problem over the tokens of the sentence. Each token is assigned a label indicating its role with respect to the predicate, using a BIO (Begin-Inside-Outside) encoding scheme to represent argument spans.

- motivate semantic role labeling

Semantic role labeling is motivated by the need for machines to understand the meaning of natural language in a structured, interpretable, and generalizable way. While syntactic parsing reveals sentence structure, it does not capture who did what to whom, or under what circumstances. Without semantic role labeling, systems cannot reliably answer questions like “Who received the book?” or “Where did the accident occur?” even if they understand the grammar of the sentence. This limitation is particularly acute in domains such as legal document analysis, clinical note interpretation, or financial reporting, where precise attribution of actions and entities is critical. Furthermore, semantic role labeling enables cross-lingual transfer, as role structures often remain consistent across languages even when surface syntax varies. The ability to accurately extract these roles from text is therefore not merely an academic exercise but a practical necessity for deploying intelligent systems in real-world, high-stakes environments.

- application of semantic role labeling

The application of semantic role labeling spans numerous domains requiring automated comprehension of textual content. In healthcare, it enables extraction of patient symptoms, treatments, and outcomes from clinical notes, improving diagnostic support systems. In legal technology, it facilitates the identification of parties, actions, and obligations in contracts and court documents, streamlining compliance and litigation analysis. In finance, it supports automated extraction of transactional relationships from news articles and earnings reports, enhancing algorithmic trading and risk assessment. In customer service automation, it allows chatbots to accurately interpret user intents and extract key entities such as dates, locations, and product names. In knowledge graph construction, semantic role labeling provides the structured triples needed to populate databases with factual relationships derived from unstructured text. The accuracy and robustness of these applications are directly tied to the performance of the underlying semantic role labeling system, making improvements in this area critical for real-world impact.

- decompose semantic role labeling into sub-tasks

Semantic role labeling is decomposed into four sequential sub-tasks: predicate identification, predicate sense disambiguation, argument identification, and role classification. Predicate identification determines which words in the sentence serve as predicates—typically verbs or nouns with semantic force. Predicate sense disambiguation resolves which specific meaning of a polysemous predicate is intended, such as distinguishing between “run” as in “run a company” versus “run a marathon.” Argument identification locates the syntactic spans or dependency nodes that serve as arguments to the predicate. Role classification assigns each identified argument a semantic role label from a predefined set, such as ARG0, ARG1, or AM-TMP. In the embodiments of the present invention, the first two sub-tasks are assumed to be preprocessed and provided as input, allowing the system to focus exclusively on the latter two: identifying argument spans and classifying their roles. This simplification enables the invention to be integrated into existing pipelines without requiring modifications to predicate detection modules.

- assume predicate is given

In the context of the present invention, the predicate is assumed to be given as part of the input, meaning that the position and sense of the target verb or noun in the sentence are already identified and annotated. This assumption is consistent with standard evaluation protocols for semantic role labeling benchmarks such as CoNLL2005 and CoNLL2009, where predicate boundaries and senses are pre-marked. By fixing the predicate, the system can concentrate its computational resources on the more challenging task of argument role classification, which requires understanding the semantic relationships between the predicate and its surrounding constituents. This assumption does not limit the applicability of the invention, as predicate identification is a well-studied subtask that can be handled by separate, optimized models, allowing the present invention to be modularly integrated into end-to-end systems.

- convert argument prediction into sequence tagging problem

The argument prediction problem is converted into a sequence tagging task by assigning each token in the sentence a label indicating its semantic role with respect to the given predicate. These labels follow a BIO encoding scheme, where “B-” denotes the beginning of an argument span, “I-” denotes continuation within the span, and “O” denotes tokens outside any argument. For example, in the sentence “John gave Mary a book,” with “gave” as the predicate, the tokens may be labeled as B-ARG0, O, B-ARG1, O, B-ARG2, O, respectively. This formulation allows the use of standard sequence labeling architectures, such as bidirectional LSTMs with conditional random field (CRF) decoding, which are highly effective at capturing long-range dependencies and enforcing label consistency across spans. The sequence tagging approach is computationally efficient, scalable to long sentences, and compatible with modern deep learning frameworks, making it the preferred method for implementing semantic role labeling in production systems.

- perform semantic role labeling using machine learning model

Semantic role labeling is performed using a deep neural network model that processes token sequences through stacked layers of word embeddings, contextual encoders, and a classification head. The model begins by mapping each token to a dense vector representation, often derived from pretrained contextual embeddings such as BERT or ELMo. These embeddings are then passed through one or more recurrent or transformer-based encoder layers that capture contextual dependencies among tokens. The output of the final encoder layer is a sequence of hidden states, each representing the contextualized meaning of a token with respect to the predicate. These hidden states are fed into a classification layer, typically a linear projection followed by a CRF decoder, which assigns each token a semantic role label. The entire model is trained end-to-end using labeled training data, minimizing a loss function that penalizes incorrect label assignments while enforcing label coherence across argument spans.

- limitations of deep learning models

Despite their success, deep learning models for semantic role labeling suffer from a fundamental limitation: they generalize poorly to low-frequency predicates and rare argument structures that are underrepresented in training data. These models rely on statistical patterns learned from large corpora, and when confronted with examples that deviate from these patterns, they tend to default to the most frequent label observed during training, even when contextually inappropriate. This behavior is exacerbated in out-of-domain settings where the distribution of predicates and roles differs significantly from the training corpus. Additionally, deep models lack explicit memory of individual training instances, making them unable to recall and adapt to specific contextual cues that may have been observed during training but are not captured by their learned parameters. As a result, even state-of-the-art models exhibit significant performance drops on rare but semantically valid constructions, limiting their reliability in practical applications.

- motivate need for addressing low-frequency exceptions

Low-frequency exceptions are not merely statistical anomalies—they are often the most semantically rich and contextually informative instances in real-world language use. In legal, medical, or technical domains, rare predicates and unusual argument structures frequently carry critical meaning, such as novel legal obligations, uncommon medical procedures, or specialized technical actions. Ignoring these exceptions leads to systematic errors that can have serious consequences in high-stakes applications. For example, a system that consistently mislabels a rare medical verb as a common one may fail to detect a critical diagnosis. Traditional approaches to addressing data sparsity, such as data augmentation or transfer learning, are insufficient because they do not preserve the fine-grained, instance-specific information that distinguishes rare cases from their frequent counterparts. There is therefore a compelling need for a mechanism that can dynamically retrieve and adapt to relevant training examples at inference time, enabling the model to correct its predictions based on direct analogies to previously seen, semantically similar contexts.

- introduce parameterized neighborhood memory adaptation

Parameterized neighborhood memory adaptation is a novel method for enhancing semantic role labeling by dynamically integrating instance-specific evidence from a memory of previously observed token activations. Unlike conventional memory-augmented models that use fixed distance metrics or unweighted neighbor voting, this invention introduces a learnable, parametric mechanism that computes a compact, context-sensitive representation of a token’s nearest neighbors in a stored activation library. This representation is not a simple average or majority vote but a weighted combination governed by trainable parameters that capture the relative relevance of each neighbor’s activation vector. By retraining the classification layers of the base model using these parametric representations, the system learns to extract and amplify the most informative signals from its memory, effectively enabling it to “remember” and apply rare but correct patterns that would otherwise be overlooked.

- define parameterized neighborhood memory adaptation

Parameterized neighborhood memory adaptation is defined as a two-phase computational procedure in which a library of token-level activation vectors is first constructed from a trained base model, and then a set of learnable neighborhood parameters is introduced to compute a compact, weighted representation of each token’s k-nearest neighbors in that library. These representations are then used to retrain the classification layers of the base model, allowing the system to learn how to optimally combine evidence from similar training instances to improve label prediction. The key innovation lies in the parameterization of the neighborhood combination: instead of using fixed weights or distances, the system learns a distinct vector for each neighbor position, enabling it to selectively emphasize or suppress contributions based on learned relevance. This approach transforms memory-based inference from a static lookup into a dynamic, adaptive process that can be fine-tuned through backpropagation.

- motivate parameterized neighborhood memory adaptation

The motivation for parameterized neighborhood memory adaptation stems from the observation that even when a deep learning model misclassifies a token, its nearest neighbors in the activation space often include examples with the correct label. This phenomenon suggests that the necessary semantic information exists in the model’s memory but is not being effectively accessed or utilized during inference. Traditional memory-augmented models attempt to address this by averaging neighbor labels or using attention mechanisms, but these methods lack the expressiveness to capture nuanced, position-specific relationships between tokens. Parameterized neighborhood memory adaptation overcomes this limitation by introducing a learnable transformation that maps the set of neighbor activations into a single, context-aware representation optimized for classification. This enables the system to not only recall relevant examples but to learn how to interpret them in a way that maximizes predictive accuracy, thereby closing the gap between statistical generalization and instance-specific adaptation.

- describe library generation phase

The library generation phase involves processing the entire training corpus through a pre-trained semantic role labeling model to extract and store the final hidden layer activations for each token, along with its corresponding true semantic role label and token identity. These activations, which encode the contextualized meaning of each token as interpreted by the model, are indexed in a persistent memory structure, organized by token type and sentence context. The library is populated only once, after the base model has converged on the training data, ensuring that the stored representations reflect the model’s learned understanding of semantic roles. The size of the library is determined by the number of tokens in the training set, but in practice, only a subset (e.g., 15%) is retained to balance memory efficiency and performance. Each entry in the library includes the activation vector, the token’s surface form, its position in the sentence, and its gold-standard role label, enabling precise retrieval during the adaptation phase.

- generate activation maps for tokens

Activation maps for tokens are generated by passing each token in the training corpus through the base semantic role labeling model and recording the output of its final hidden layer. These activation maps are dense, high-dimensional vectors that capture the token’s contextual meaning in relation to the predicate and surrounding arguments. Unlike word embeddings, which are static and context-independent, activation maps are dynamic and reflect the model’s internal interpretation of the token’s role within its specific syntactic and semantic environment. For example, the word “book” may have different activation maps when appearing as an ARG1 in “I read a book” versus an ARG0 in “The book arrived yesterday.” These distinctions are preserved in the activation maps, making them ideal for identifying semantically similar instances during neighborhood search.

- record activation maps in library

The activation maps are recorded in a structured memory library indexed by token identifier and sentence context. Each entry in the library contains the activation vector, the token’s surface form, its position within the sentence, the predicate it relates to, and its gold-standard semantic role label. This indexing allows for efficient retrieval during inference, enabling the system to locate tokens with similar contextual representations even if their surface forms differ. The library is stored in a manner that supports fast k-nearest neighbor searches using Euclidean distance, and it is maintained as a static resource after generation, ensuring that the adaptation phase operates independently of the base model’s training process. The library is not updated during inference, preserving the integrity of the learned representations and preventing overfitting to new inputs.

- describe neighborhood parameterization phase

The neighborhood parameterization phase introduces a set of learnable parameters that define how the k-nearest neighbors of a token are combined to form a single, compact representation. These parameters are initialized randomly and optimized during a retraining phase using backpropagation. For each token in the training set, the system identifies its k-nearest neighbors in the library based on Euclidean distance between activation vectors. It then computes a weighted combination of the neighbors’ activation vectors using the learnable parameters, producing a neighborhood parametric representation that encodes the most relevant contextual signals from the memory. This representation is designed to be more informative than the original token activation, as it incorporates evidence from semantically similar instances that may have been misclassified by the base model.

- initialize learnable neighborhood parameters

Learnable neighborhood parameters are initialized as a set of k distinct, trainable vectors, each corresponding to one of the k nearest neighbors. These vectors are of the same dimensionality as the activation maps and are initialized using a standard random initialization scheme, such as Xavier or He initialization. Each parameter vector is associated with a specific neighbor position (e.g., first nearest, second nearest, etc.) and is not tied to any particular token or label, allowing the system to generalize across different contexts. The parameters are not constrained during initialization, enabling the optimization process to discover the optimal weighting scheme for combining neighbor activations based on their contribution to accurate classification.

- generate activation maps for input sentence

During inference, activation maps for the input sentence are generated by passing the sentence through the frozen base model, exactly as during the library generation phase. The same word embeddings, encoder layers, and preprocessing steps are applied to ensure consistency with the training data. The output of the final hidden layer is a sequence of activation vectors, one for each token in the sentence. These vectors are not modified or retrained during inference but are used solely to locate their nearest neighbors in the static library. The use of the frozen base model ensures that the system’s understanding of token meaning remains consistent with the knowledge encoded during initial training, while the neighborhood adaptation provides a dynamic correction mechanism.

- identify nearest neighbors in library

The nearest neighbors in the library are identified by computing the Euclidean distance between the activation vector of each input token and all activation vectors stored in the library. The k tokens with the smallest distances are selected as the nearest neighbors, regardless of their surface form or role label. This process is performed efficiently using approximate nearest neighbor search algorithms, such as locality-sensitive hashing or tree-based indexing, to ensure scalability to large libraries. The selection is purely based on activation similarity, allowing the system to retrieve semantically analogous tokens even if they differ syntactically or lexically. For example, a rare verb may find its nearest neighbors among other rare verbs with similar argument structures, even if they are not synonyms.

- combine learnable neighborhood parameters with nearest neighbors

The learnable neighborhood parameters are combined with the activation vectors of the nearest neighbors through a weighted summation operation. Each neighbor’s activation vector is multiplied element-wise by its corresponding learnable parameter vector, and the results are summed to produce a single neighborhood parametric representation. This operation is differentiable, enabling the parameters to be optimized during retraining. The combination is not a simple average but a learned transformation that assigns different weights to different neighbor positions, allowing the system to prioritize certain neighbors over others based on their observed contribution to correct predictions. This mechanism enables the model to learn which neighbors are most informative for a given token type or role.

- compute neighborhood parametric representation

The neighborhood parametric representation is computed as the sum of the element-wise products between each neighbor’s activation vector and its corresponding learnable parameter vector. This results in a single vector of the same dimensionality as the original token activation, but enriched with contextual evidence from the memory. The representation is designed to capture not just the presence of similar instances but the direction and magnitude of their influence on correct classification. For example, if the majority of neighbors suggest a particular role label, the parametric representation will be biased toward that label, even if the base model’s own activation was ambiguous or incorrect. This representation serves as the enhanced input to the classification layer, replacing or augmenting the original token activation.

- feed neighborhood parametric representation to remaining hidden layers

The neighborhood parametric representation is fed into the remaining hidden layers of the base model, which are frozen and unchanged from the initial training phase. Since the encoder layers are not retrained during the adaptation phase, the parametric representation is treated as a modified input to the classification head. The classification layer, which has been retrained using these representations, learns to interpret the enhanced activations and map them to the correct semantic role labels. This ensures that the system benefits from both the deep contextual understanding of the base model and the instance-specific refinement provided by the neighborhood adaptation, without introducing additional computational overhead during inference.

- output labels predicting semantic roles

The final output of the system is a sequence of semantic role labels, one for each token in the input sentence, generated by applying the retrained classification layer to the neighborhood parametric representations. These labels are produced using a conditional random field (CRF) decoder to ensure label consistency across argument spans and to enforce global constraints such as non-overlapping roles and proper BIO formatting. The output is identical in format to that of a standard semantic role labeling system but achieves higher accuracy, particularly for low-frequency predicates and rare argument structures. The system thus delivers a more robust and reliable prediction than conventional models, without requiring additional training data or architectural changes.

- update learnable neighborhood parameters via backpropagation

The learnable neighborhood parameters are updated during the retraining phase using standard backpropagation through the entire computational graph, including the distance computation, neighbor selection, parametric combination, and classification layers. The loss function is computed as the cross-entropy between the predicted labels and the ground truth labels for the training set. Gradients are propagated backward from the classification layer through the parametric combination layer, then to the neighbor activation vectors and finally to the neighborhood parameters. This enables the system to learn which neighbors are most informative for each token and how to weight their contributions to maximize classification accuracy. The parameters are updated iteratively over multiple epochs until convergence, resulting in a refined set of weights that optimally exploit the memory library.

- describe improved performance of deep learning model

The improved performance of the deep learning model is demonstrated through empirical evaluation on standard benchmark datasets, including CoNLL2005, CoNLL2012, and CoNLL2009. The proposed system consistently outperforms baseline models, achieving state-of-the-art F1 scores across both in-domain and out-of-domain test sets. The gains are most pronounced on low-frequency predicates, where the base model alone exhibits significant performance degradation. The improvement is not attributable to increased model size or additional training data but to the effective integration of instance-specific memory into the classification process. The system demonstrates robustness across different embedding types, including randomly initialized embeddings, ELMo, and BERT, confirming its generalizability. The performance gains are statistically significant and reproducible across multiple random seeds, validating the reliability of the method.

A computerized tool is introduced that implements the parameterized neighborhood memory adaptation method for semantic role labeling. This tool is a software system that executes the full pipeline of library generation, neighborhood parameterization, and model retraining on a computing device with sufficient memory and processing power. The tool accepts as input a training corpus and a pre-trained semantic role labeling model, and outputs a retrained model capable of performing semantic role labeling with enhanced accuracy on rare and low-frequency instances. The tool is implemented as a modular software package compatible with standard deep learning frameworks such as PyTorch or TensorFlow, and includes utilities for library management, neighbor search, and parameter optimization.

The computerized tool comprises four core components: a receiver component, a library component, a parametric component, and an execution component. The receiver component parses input sentences and prepares them for processing by the base model. The library component manages the storage and retrieval of activation vectors from the memory library. The parametric component computes the neighborhood parametric representations using the learnable parameters. The execution component integrates these representations into the classification pipeline and generates the final output. These components are implemented as interconnected modules that communicate through standardized data interfaces, allowing for flexibility in deployment and integration with external systems.

- describe receiver component

The receiver component is responsible for ingesting raw text input and converting it into a sequence of tokens annotated with predicate indicators. It performs tokenization, sentence segmentation, and predicate marking according to the format expected by the base model. The component ensures that the input is consistent with the training data, including handling of punctuation, capitalization, and special characters. It may also integrate with external tools for predicate identification if the predicate is not provided. The receiver component outputs a structured representation of the sentence that is passed to the library and parametric components for further processing.

- describe library component

The library component maintains a persistent, indexed memory of activation vectors generated during the initial training phase. It supports fast retrieval of k-nearest neighbors for any given activation vector using efficient distance computation algorithms. The component stores each activation vector along with its associated token, role label, and sentence context, enabling precise matching during inference. It is designed for scalability, supporting libraries of millions of entries, and includes mechanisms for compression, caching, and distributed storage. The library component operates independently of the base model and is loaded once at system initialization, ensuring that the adaptation process does not interfere with the original model’s parameters.

- describe parametric component and execution component

The parametric component computes the neighborhood parametric representation for each token by combining its k-nearest neighbors using the learnable parameters. It performs distance-based neighbor selection, vector multiplication, and summation to produce a single enhanced representation for each token. The execution component receives these representations and feeds them into the retrained classification layer of the base model. It applies the CRF decoder to ensure label consistency and outputs the final semantic role labels. The parametric and execution components operate in tandem during both training and inference, with the parametric component dynamically generating inputs and the execution component producing predictions based on those inputs.

- define parametric component

The parametric component is defined as a differentiable module that takes as input a token’s activation vector and a library of stored activation vectors, and outputs a neighborhood parametric representation computed as a weighted sum of the k-nearest neighbors, where the weights are determined by a set of learnable parameters. The component includes a distance computation module, a neighbor selection module, and a parametric combination module, all of which are implemented as differentiable operations to enable end-to-end training. The parametric component is agnostic to the underlying model architecture and can be integrated with any sequence labeling system that produces contextualized token representations.

- create neighborhood parameters

Neighborhood parameters are created as a set of k trainable vectors, each of dimensionality equal to the activation vector size. These vectors are initialized randomly and optimized during the retraining phase using gradient descent. Each parameter vector corresponds to a specific neighbor position (e.g., first, second, ..., k-th nearest) and is not tied to any particular token or label. The parameters are stored as a matrix and updated iteratively during training to minimize classification error. The creation of these parameters is fully automated and requires no manual configuration.

- retrain labeler with neighborhood parameters

The labeler is retrained using the neighborhood parametric representations as inputs instead of the original token activations. The weights of the base model’s encoder and embedding layers are frozen, and only the classification layer and the neighborhood parameters are updated. The retraining is performed over multiple epochs using the same training corpus, with the loss computed based on the difference between predicted and true semantic role labels. This process allows the labeler to learn how to interpret the enhanced representations and map them to the correct labels, effectively incorporating the memory-based evidence into its decision-making process.

- generate token activation maps

Token activation maps are generated by passing each token in the training corpus through the base model’s encoder layers and recording the output of the final hidden layer. These maps are high-dimensional vectors that encapsulate the token’s contextual meaning as interpreted by the model. They are generated only once during the library generation phase and are not recomputed during inference. The activation maps are stored in the library along with their corresponding token identities and role labels, forming the foundation for the neighborhood adaptation process.

- identify k nearest neighbors

The k nearest neighbors for each token are identified by computing the Euclidean distance between its activation vector and all activation vectors in the library. The k vectors with the smallest distances are selected as neighbors, regardless of their surface form or role label. This process is performed using efficient approximate nearest neighbor algorithms to ensure scalability. The selection is based purely on activation similarity, allowing the system to retrieve semantically analogous tokens even if they differ lexically or syntactically.

The neighbors are combined with the neighborhood parameters through an element-wise multiplication and summation operation. - generate neighborhood parametric representation

The neighborhood parametric representation is generated as the sum of the element-wise products between each neighbor’s activation vector and its corresponding learnable parameter vector. The neighborhood parametric representations are fed into the retrained classification layer of the base model, which has been optimized to interpret these enhanced inputs. The output is then passed through a conditional random field (CRF) decoder to enforce label consistency across argument spans. The entire process is fully differentiable, allowing the system to learn how to optimally combine memory-based evidence with the base model’s predictions.

- compute loss and update parameters

The loss is computed as the cross-entropy between the predicted semantic role labels and the ground truth labels for the training set. Gradients are computed with respect to both the classification layer weights and the neighborhood parameters, and these gradients are used to update the parameters via stochastic gradient descent. The base model’s encoder and embedding layers remain frozen during this phase. The loss computation and parameter updates are performed iteratively over multiple epochs until convergence, resulting in a refined set of neighborhood parameters that maximize classification accuracy.

- repeat process for entire training dataset

The process of computing neighborhood parametric representations, feeding them to the labeler, computing loss, and updating parameters is repeated for every token in the training dataset across multiple epochs. This ensures that the neighborhood parameters are optimized to generalize across all types of tokens and roles, not just a subset. The system learns to adapt its memory-based reasoning to the full distribution of semantic roles in the training corpus, resulting in a robust and reliable model.

The k activation maps with the smallest distances are selected as the nearest neighbors. This process is performed independently for each token and does not depend on surface form or syntactic structure, allowing the system to retrieve semantically analogous tokens even if they differ lexically.

- combine neighbors with neighborhood parameters

The neighbors are combined with the neighborhood parameters through a learned, element-wise multiplication and summation operation. Each neighbor’s activation vector is multiplied by its corresponding learnable parameter vector, and the results are summed to produce a single neighborhood parametric representation. This operation is differentiable and enables the parameters to be optimized during training, allowing the system to learn which neighbors are most informative for each token type.

- generate neighborhood parametric representation

The neighborhood parametric representation is generated as the sum of the element-wise products between each neighbor’s activation vector and its corresponding learnable parameter vector. This results in a single vector that encodes the most relevant contextual signals from the memory, enhancing the original token representation with evidence from similar training instances.

- feed neighborhood parametric representations to labeler

The neighborhood parametric representations are fed into the retrained classification layer of the base model, which has been optimized to interpret these enhanced inputs. The classification layer maps each representation to a semantic role label using a linear projection followed by a softmax function. The output is then passed through a conditional random field (CRF) decoder to enforce label consistency across argument spans.

- generate labels for input sentence

The final output is a sequence of semantic role labels, one for each token in the input sentence, generated by the CRF-decoded classification layer. These labels indicate the semantic role played by each token with respect to the given predicate, such as ARG0, ARG1, or AM-TMP. The labels are formatted using the BIO encoding scheme to represent argument spans and are output in a structured format suitable for downstream applications.

- provide example of SRL model training

An example of SRL model training begins with a base model trained on the CoNLL2005 corpus using BERT embeddings. After convergence, activation maps are generated for each token in the training set and stored in a library. A set of 64 learnable neighborhood parameters is initialized. For each token, the 64 nearest neighbors are identified using Euclidean distance. The neighborhood parametric representation is computed by combining the neighbors’ activation vectors with the learnable parameters. The classification layer is retrained for 20 epochs using these representations, while the base model’s encoder remains frozen. The final model achieves a 0.9-point improvement in F1 score on the out-of-domain Brown test set compared to the base model.

- generate library of token activation maps

The library of token activation maps is generated by processing the entire training corpus through the base model and recording the final hidden layer activations for each token. Each activation map is indexed by token identity, predicate, and role label. The library is stored in a compressed format to reduce memory usage and supports fast retrieval during inference.

- randomly initialize neighborhood parameters

Neighborhood parameters are randomly initialized as a matrix of size k × d, where k is the number of neighbors and d is the dimensionality of the activation vectors. The initialization uses a standard scheme such as Xavier uniform to ensure stable training dynamics. These parameters are not tied to any specific token or label and are optimized during retraining to maximize classification accuracy.

- identify nearest neighbors for each token

For each token in the training set, the k nearest neighbors are identified by computing the Euclidean distance between its activation vector and all vectors in the library. The k vectors with the smallest distances are selected as neighbors, regardless of their surface form or role label. This process is performed for every token in the training set.

- compute Euclidean distance

Euclidean distance is computed between each token’s activation vector and every activation vector in the library using the standard formula: the square root of the sum of squared differences between corresponding elements. This distance metric is chosen for its simplicity, interpretability, and compatibility with gradient-based optimization.

- select k nearest neighbors

The k nearest neighbors are selected by sorting the computed distances in ascending order and retaining the first k entries. This selection is performed independently for each token and is deterministic given the same library and activation vector.

- generate neighborhood parametric representation

The neighborhood parametric representation is generated by multiplying each neighbor’s activation vector by its corresponding learnable parameter vector and summing the results. This produces a single vector that encodes the most relevant evidence from the memory, enhancing the original token representation.

- feed representations to labeler

The neighborhood parametric representations are fed into the retrained classification layer, which maps them to semantic role labels. The classification layer has been optimized during retraining to interpret these enhanced inputs and produce accurate predictions.

- compute loss and update parameters

The loss is computed as the cross-entropy between the predicted labels and the ground truth labels. Gradients are computed with respect to the classification layer weights and the neighborhood parameters, and these gradients are used to update the parameters via stochastic gradient descent.

- repeat process for entire training dataset

The process of computing neighborhood parametric representations, feeding them to the labeler, computing loss, and updating parameters is repeated for every token in the training dataset across multiple epochs. This ensures that the neighborhood parameters are optimized to generalize across all types of tokens and roles.
