## TECHNICAL FIELD

The present invention relates to secure multiparty computation protocols designed to enable privacy-preserving comparisons between integers held by distinct parties without revealing any information beyond the outcome of the comparison. Specifically, the invention provides a non-interactive, homomorphic encryption-based framework for performing secure integer comparison operations in a client-server architecture, wherein one party holds a private input to be compared against another party’s private input, and only the result of the comparison is disclosed to the requesting party. The protocol is applicable in environments where data confidentiality is paramount, including but not limited to secure auctions, private machine learning inference, enterprise benchmarking, biometric authentication, and privacy-preserving analytics. The invention leverages the algebraic properties of homomorphic encryption schemes—both additively homomorphic and fully homomorphic—to evaluate a structured binary tree representation of one party’s input using the encrypted input of the other party, thereby ensuring that no intermediate values or input data are exposed during computation. The protocol operates in a single communication round, eliminating the need for iterative exchanges and significantly reducing latency and vulnerability to timing-based attacks. This technical advancement enables scalable deployment in real-world systems where computational efficiency, minimal interaction, and strong cryptographic guarantees are simultaneously required.

## RELATED ART

Secure multiparty computation has long been a cornerstone of cryptographic privacy research, with foundational work dating back to Yao’s Millionaires’ Problem, which posed the challenge of determining which of two parties holds a larger integer without disclosing either party’s actual value. Early solutions to this problem relied on garbled circuits, which, while theoretically sound, incurred prohibitive communication and computational overheads for large inputs. Subsequent approaches introduced arithmetic-based protocols using homomorphic encryption, notably the DGK protocol, which employed additively homomorphic encryption to compare bit representations of integers through iterative evaluation of encrypted comparisons. These methods, though more efficient than garbled circuits, still required multiple rounds of interaction, introduced significant computational complexity due to repeated modular operations, and often depended on specific encryption schemes such as Paillier or specialized variants of ElGamal. Further optimizations attempted to reduce the number of ciphertexts transmitted or to minimize the number of homomorphic operations, yet they invariably retained multi-round communication patterns or introduced additional assumptions such as secure channels, offline preprocessing, or reliance on specific homomorphic properties that limited their generality. Other approaches attempted to leverage the arithmetic black-box model or secret sharing, but these typically required more than two parties, assumed symmetric roles among participants, or introduced dependencies on Beaver triples and secure channel infrastructure. Crucially, none of these prior methods achieved a truly non-interactive protocol that simultaneously supported encrypted inputs, shared outputs, and logarithmic multiplicative depth for fully homomorphic encryption without sacrificing correctness or security. Moreover, existing protocols failed to provide a unified framework capable of seamlessly adapting between additively homomorphic and fully homomorphic encryption schemes while preserving the same structural logic and communication pattern. The limitations of these prior systems—namely, their multi-round nature, scheme-specific constraints, and inability to handle encrypted server inputs without additional cryptographic overhead—have hindered their practical adoption in latency-sensitive, privacy-critical applications.

## SUMMARY

The invention introduces a novel, non-interactive protocol for secure integer comparison that enables a client to determine whether its private integer is greater than or equal to a server’s private integer, without either party revealing any information beyond the final comparison result. The first embodiment of the invention utilizes a homomorphic encryption scheme under which the server constructs a binary tree structure representing its input, and the client encrypts its own input and transmits it to the server for evaluation. The server evaluates the encrypted client input against the tree by computing bit-level equality or inequality operations homomorphically, aggregates decision bits along all possible paths, and returns a single encrypted bit to the client, which decrypts to reveal the comparison outcome. The second embodiment extends this framework to support scenarios where both the client and server inputs are encrypted, employing a generalized binary tree structure known as a normal comparison tree that encodes the server’s input in a fixed, input-independent topology. This allows the server to perform all computations on encrypted data without learning any information about the client’s input, while the client retains the ability to decrypt the final result. The third embodiment introduces an optimized implementation using a two-dimensional array representation of the binary tree, enabling efficient evaluation through precomputed dependency lists that reduce the multiplicative depth of fully homomorphic encryption operations from linear to logarithmic, thereby significantly improving performance in leveled FHE settings. The invention further demonstrates the application of homomorphic encryption to support less-than comparisons, shared output bits, and zero-input handling through minor structural modifications to the underlying tree construction. The primary advantage of this protocol lies in its non-interactive nature, requiring only a single message exchange between client and server, and its ability to operate under both additively homomorphic and fully homomorphic encryption schemes without altering the core protocol logic. This unified design eliminates the need for multiple rounds, preprocessing, or secure channels, while maintaining semantic correctness and IND-CPA security under standard cryptographic assumptions.

## DETAILED DESCRIPTION

The invention provides a secure integer comparison protocol based on the evaluation of a binary tree structure constructed by the server and evaluated by the client using homomorphic encryption. The protocol begins with the client generating a public-private key pair for a homomorphic encryption scheme and transmitting the public key and evaluation key to the server. The server, possessing a private integer input, constructs a binary tree whose structure encodes the bit representation of its input. Each edge in the tree is labeled with a bit value, and each leaf node is assigned a label indicating whether the corresponding path represents an input greater than or equal to the server’s value. The client then encrypts its own integer input bit by bit and sends the resulting ciphertexts to the server. The server evaluates the encrypted client input against the tree by performing homomorphic operations to determine bit equality or inequality along each path, aggregating these decisions multiplicatively for fully homomorphic encryption or additively for additively homomorphic encryption. For fully homomorphic encryption, the server computes a product of decision bits along each path, and then sums the products weighted by the leaf labels to produce a single encrypted bit. For additively homomorphic encryption, the server computes a sum of decision bits along each path, applies a power-of-two scaling to prevent cancellation of negative values, randomizes the resulting ciphertexts, permutes their order, and transmits the set to the client. The client decrypts the result and interprets the output: in the fully homomorphic case, a decrypted bit directly indicates the comparison outcome; in the additively homomorphic case, the presence of a zero-valued ciphertext among the set indicates a true comparison result. The protocol supports extensions such as shared output bits, where the server randomly chooses a bit and computes a homomorphic XOR with the result, enabling both parties to reconstruct the final bit through local combination. The server’s input may remain in plaintext or be encrypted, with the latter requiring the use of a normal comparison tree structure that ensures the tree’s topology remains invariant regardless of the server’s actual value. This normalization allows the server to evaluate encrypted inputs without revealing structural information. The protocol further incorporates an optimized implementation using a two-dimensional array to represent the tree, where each row corresponds to a bit position and each column stores decision bits, edge labels, and leaf values. A precomputed dependency list identifies which array elements must be multiplied together to compute path aggregations, enabling the server to evaluate the tree with logarithmic multiplicative depth rather than linear depth. This optimization is particularly valuable in leveled fully homomorphic encryption systems, where circuit depth directly impacts performance. The protocol is implemented using standard homomorphic encryption algorithms, including key generation, encryption, evaluation, and decryption functions, and satisfies correctness conditions under which the decrypted output always matches the intended comparison result. Security is guaranteed under the IND-CPA assumption, as the server operates solely on encrypted inputs and returns only randomized, permuted ciphertexts that reveal no information about the server’s input or the internal structure of the tree. The protocol requires no secure channels, no offline preprocessing, and no multi-round interaction, making it uniquely suited for deployment in real-time, privacy-sensitive applications such as secure auctions, private machine learning classification, and biometric matching systems.
